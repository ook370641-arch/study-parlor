## A 类：已实现功能

### A0 夜航简报

**状态结构**
- `store.briefing: { result: BriefingResult | null, loading: boolean, error: string | null }`
- `store.briefingHistory: { list: { date: string; filePath: string }[], loading: boolean, error: string | null }`

**IPC**
- `briefing:generate({ date, profile, force? })` → `BriefingResult`
- `briefing:list()` → `{ date: string; filePath: string }[]`

**文件缓存**
- 目录：`<libraryPath>/夜航简报/`
- 文件：`<libraryPath>/夜航简报/夜航简报-YYYY-MM-DD.md`
- frontmatter：`type: 'briefing'`, `title: '夜航简报'`, `tags: ['industry-digest', 'ai']`, `briefing_sources: JSON.stringify(sources)`

**错误码**
- `FEED_EMPTY`：三个 feed 都为空。
- 网络失败：通用错误提示。
- `cacheWriteFailed`：缓存写入失败，但结果仍返回。

**E2E 关注点**
- Cover → Briefing 导航。
- 有缓存时直接展示；无缓存时生成。
- loading 状态。
- 历史列表侧栏切换。
- 重新生成按钮。
- 空 feed/断网错误提示。

**E2E 辅助**
- 新增 `seedBriefing(libPath, date)` helper，在临时学习库预写 `夜航简报-YYYY-MM-DD.md`，用于 `@smoke` 缓存命中场景。
- 新增环境变量覆盖 feed URL（`BRIEFING_FEED_X_URL`、`BRIEFING_FEED_PODCASTS_URL`、`BRIEFING_FEED_BLOGS_URL`），让 E2E 可以启动本地 server 稳定复现 `FEED_EMPTY`、网络失败等错误路径，而不必依赖真实 GitHub feed。

**E2E 场景矩阵**

| 场景 | 标记 | 前置条件 | 关键断言 |
|---|---|---|---|
| Cover → Briefing 导航 | `@smoke` | 应用启动到 Cover | 点击 briefing button 后进入 briefing 页面 |
| 有缓存时直接展示 | `@smoke` | `seedBriefing` 预写当天简报 | 标题、日期、内容区渲染；不触发 LLM |
| 无缓存时展示 loading | `@smoke` | 选择未来日期无缓存 | `BriefingSkeleton` 出现 |
| 历史侧栏切换 | `@smoke` | 预写多份不同日期简报 | 点击"往期"后列出日期；点击日期切换内容 |
| 重新生成 | `@smoke` | 有缓存 | 点击重新生成后触发 `briefing:generate({ force: true })` |
| FEED_EMPTY 错误 | `@smoke` | feed URL 指向返回空数组的本地 server | 显示"今日海面平静，暂无新信号。" |
| 网络失败错误 | `@smoke` | feed URL 指向返回 500 的本地 server | 显示错误提示与重试按钮 |
| cacheWriteFailed | `@smoke` | 学习库目录只读 | 页面显示"（本次未写入缓存）" |
| 真实生成 happy path | `@unstable` | 外网正常、Kimi 可用 | 内容非空、文件写入 `夜航简报/` |

### A1 网络搜索（外部资料）

**状态结构**
- `store.externalMaterials: { summary: string | null, sources: SearchSource[], loading: boolean, error: SearchErrorCode | null } | null`

**IPC**
- `search:checkConfig()` → `{ configured: boolean }`
- `search:setApiKey(key)` → void
- `search:prepare({ topic })` → `SearchResult`

**配置**
- Tavily API Key 独立存储于 credentials，不在 `.env`。

**错误码**
- `MISSING_API_KEY`
- `NETWORK_ERROR`
- `LLM_ERROR`
- `NO_RESULTS`

**LLM 调用链**
1. `generateSearchQueries(cfg, topic)`：生成 3 个搜索查询。
2. `searchWeb({ query, apiKey, maxResults })`：Tavily 搜索，单查询失败不影响其他。
3. `generateTutorBrief(cfg, topic, results)`：生成 3000 中文字以内摘要。

**注入方式**
- `startSession` 时通过 `externalMaterialsSummary` 传入 LLM 上下文。

**归档**
- 生成 `<主题目录>/外部资料-第N次.md`。
- frontmatter：`type: 'external-materials'`。

**E2E 隔离**
- Tavily API Key 加密存储于 `~/.studyparlor/search-key.enc`，由 `electron/lib/credentials.ts` 管理。
- E2E fixture 已通过 `E2E_CONFIG_DIR` 隔离 `.env` 与 `state.json`；需同步让 credentials 目录也指向临时配置目录（复用 `E2E_CONFIG_DIR`），否则测试会读到/污染真实用户的 key。

**E2E 场景矩阵**

| 场景 | 标记 | 前置条件 | 关键断言 |
|---|---|---|---|
| PreStudy 未配置 key 时点 toggle 提示配置 | `@smoke` | 临时 credentials 目录无 `search-key.enc` | 出现 toast"请先在设置中配置 Tavily API Key" |
| 设置页保存 Tavily key 后状态变为已配置 | `@smoke` | 同上 | `settings-search-save-button` 点击后返回，PreStudy toggle 不再提示 |
| 勾选外部资料后开始学习，生成外部资料归档 | `@unstable` | 已配置真实/测试 key | `external-materials-card` 出现摘要与来源；学习目录生成 `外部资料-第N次.md` |
| 无搜索结果时显示"未找到相关外部资料" | `@unstable` | 使用真实 Tavily，搜索极冷门主题 | `external-materials-card` 显示 NO_RESULTS 文案 |
| 网络错误时显示"外部资料获取失败" | `@unstable` | 断开外网或 Tavily 异常 | 卡片显示 NETWORK_ERROR 文案，不影响开始学习 |

### A2 DIY 术语

**类型定义**
```ts
export type Terminology = {
  sessionName?: string
  libraryName?: string
  archiveVerb?: string
  // ... 共 30+ 个字段
}
```

**状态**
- `store.terminology: Terminology`
- 持久化：`state.json.terminology`

**入口**
- `Cover` → `Home` → `extension` 页面。

**页面**
- `src/pages/Extension.tsx`
- 组件：`TerminologyPanel.tsx`
- 辅助：`src/lib/terminology.ts`、`src/lib/terminology-defaults.ts`

**行为**
- 读取：`terminology[key] ?? defaultValue`
- 保存：`store.patchTerminology(patch)` → 写入 `state.json`
- 重置：`store.resetTerminology()` → 清空 `state.json.terminology`
- 空字符串视为未自定义（删除键）。

**E2E 关注点**
- 进入 Extension 页面，术语面板渲染正常。
- 抽样测试字段（`sessionName`、`archiveVerb`、`difficultyLabel`、`homeGreeting`、`topicInputLabel`）修改后，Cover/Home/PreStudy/Study/Profile 对应文案同步变化。
- 修改后重启应用，自定义值仍从 `state.json` 恢复。
- 点击"恢复默认"后，所有字段回到 `DEFAULT_TERMINOLOGY`。

**抽样理由**：30+ 字段全部遍历成本高、收益低；每个类别选一个高频出现的字段即可覆盖渲染同步机制。若后续某字段单独出 bug，再补充针对性用例。

## B 类：待实现功能

### B1 内部资料读取

**状态结构（变更）**
将现有 `store.externalMaterials` 重构成统一的 `preStudyMaterials`：

```ts
{
  web: {
    summary: string | null
    sources: SearchSource[]
    note: string
    loading: boolean
    error: SearchErrorCode | null
  } | null,
  internal: {
    files: { name: string; path: string; size: number; content: string }[]
    note: string
    loading: boolean
    error: string | null
  } | null
}
```

**入口**
- `PreStudyModal` 中新增"内部资料"勾选框，与"外部资料"并列。
- 两个选项可同时勾选。
- 勾选"内部资料"后，展开"使用方式"备注输入框，用户可填写对资料的使用意图（如"我想了解这段代码实现的功能"）。
- 勾选"外部资料"后，对称展开备注输入框，用户用自然语言描述使用意图与搜索倾向（如"重点补充哪些观点或背景""广泛搜索该领域最新动态""精确搜索少量经典博客或文献"）。

**备注字段与生命周期**
- `preStudyMaterials.web.note` 与 `preStudyMaterials.internal.note` 默认值为空字符串 `''`。
- 取消勾选期间保留已输入的备注内容，再次勾选时恢复。
- 备注限制 500 字符，支持多行文本。
- 空备注（空字符串）视为未填写，归档时不生成 `### 使用意图` 小节。

**文件选择**
- 使用 `electron/dialog.showOpenDialog`。
- 支持多选，最多 5 个。
- UI 显示支持格式列表：`.md`、`.pdf`、`.txt`、代码文件。

**支持文件类型**
- `.md`、`.txt`
- `.pdf`（需引入 `pdf-parse` 或 `pdf2json`）
- 代码文件：`.js`、`.ts`、`.jsx`、`.tsx`、`.py`、`.java`、`.go`、`.rs`、`.cpp`、`.c`、`.h`、`.html`、`.css`、`.scss`、`.json`、`.yaml`、`.yml`、`.sql`

**文件处理流程**
1. 用户选择文件。
2. 主进程读取/解析每个文件：
   - 文本/代码：`fs.readFileSync`
   - PDF：`pdf-parse`
3. 将文件内容复制到 `<主题目录>/sN/source/`，文件命名为 `内部资料-原文件名`，与外部资料归档文件区分。
4. 返回文件元数据 + 内容给渲染进程。
5. 开始学习时，将内部资料全文及使用方式备注注入 LLM 上下文。

**摘要策略**
- V2 先不做摘要，直接全量注入。
- 后续再考虑：截断提示、生成摘要、按模型动态阈值。

**限制策略**
- V2 先不做文件大小/token 限制。
- 后续再考虑：单文件 5MB、总 token 阈值、模型上下文上限保护。

**错误处理**
- 单个文件读取/解析失败时，显示具体错误，跳过该文件。
- 其他文件正常加载。
- 错误文案示例："无法读取 XX.pdf，已跳过；其余 2 个文件已加载。"

**上下文注入**
- 内部资料与外部资料可同时使用。
- 注入顺序与格式（合并为单一 Markdown 字符串注入）：

  ```markdown
  ## 外部资料
  <外部资料摘要>

  ### 使用意图
  <外部资料备注>

  ## 内部资料
  ### 使用意图
  <内部资料备注>

  ### 文件内容
  <内部资料全文>
  ```

- 外部资料备注同时注入 `generateSearchQueries` 与 `generateTutorBrief` 两个阶段，具体如何影响 Tavily 查询参数（如 `maxResults`、`searchDepth`）留待实现时确定。
- 由当前 `llmStart` 的 `externalMaterialsSummary` 扩展为支持多段内容，或合并为单一字符串注入。

**归档**
- 外部资料归档 `<主题目录>/sN/外部资料-第N次.md` 的 body 中，在摘要后追加 `### 使用意图` 小节写入外部资料备注（非空才写）。
- 内部资料归档生成独立的 `内部资料.md`：
  - `<主题目录>/sN/内部资料.md`：`type: 'internal-materials'`（新增 DocType）
- `内部资料.md` 中保留全文、用户使用方式备注，并记录原始文件名和复制后的路径（`<主题目录>/sN/source/内部资料-原文件名`）。

**新增 DocType**
- `'internal-materials'`

**新增/扩展 IPC**
- `search:prepare({ topic, note? })` → `SearchResult`（扩展 A1 已有 IPC，接收外部资料备注；具体如何影响查询生成留待实现时确定）。
- `internalMaterials:prepare({ files: string[] })` → 返回文件内容列表。
- 或复用 `search:prepare`，改为 `materials:prepare` 统一处理 web/internal。

**依赖**
- `pdf-parse` 或 `pdf2json`（PDF 文本提取）
- `electron/dialog`（文件选择）

**E2E 关注点**
- PreStudy 选择内部资料后显示内容/文件名列表。

### B3 用户画像（学者书房全景图）

**目标**
自动扫描学习库，为用户生成一幅只读的学习全景图。帮助用户看清自己的学习历史、习惯与知识分布。

**入口**
- `Profile` 页面扩展，新增全景图入口（名称留待决策，如"全景图"或"学者星穹"）。

**核心原则**
- **只读可视化，不做推荐**：避免与 `group-inspiration`、`wildcard`、`continue-topic` 重叠。
- **放飞但可控**：知识星图做 MVP，视觉效果优先，失败后不影响核心功能。

**四个可视化模块**

1. **书房概览（Stats Cards）**
   - 主题总数：学习库中主题目录数。
   - 夜话/session 总数：所有主题下 `sN/` 目录总数。
   - 连续学习天数：按天去重后，最近连续有学习的天数（一天多次学习只算一天）。
   - 最近学习距今天数：从 `last_studied` 计算。
   - 视觉：深褐卡片 + 米色数字 + 暖橙强调。

2. **学习节律（Learning Rhythm）**
   - GitHub contributions 风格热力图。
   - 横轴：周；纵轴：星期。
   - 颜色深浅表示**当天学习次数**（不计算时长）。
   - 悬停显示当天学过的主题。

3. **分组分布（Group Distribution）**
   - 横向条形图或极坐标图。
   - 每个分组一个条，长度 = 主题数/session 数。
   - 颜色与 Home 分组颜色一致。

4. **学者星穹（Knowledge Constellation）**
   - 力导向知识星图。
   - 节点 = 主题，大小 ∝ session 数量，颜色 = 分组。
   - 边 = 共享 tag，边的权重 = 共享 tag 数。
   - 辅规则：基于标题/`progress_summary` 关键词共现补充弱边。
   - V2 不做 LLM 异步生成"隐藏关系"虚线边（留待 V3 决策）。
   - 交互：缩放、拖拽画布；悬停显示主题名；点击节点进入主题；点击节点高亮邻居。
   - 性能：默认显示最近/最相关的 50 个主题，提供"显示全部"。

**数据来源**
- 扫描所有 `.md` 的 frontmatter：`title`、`tags`、`type`、`created`、`last_studied`、`progress_summary`。
- 主题目录结构：`学习报告.md`、`复习记录.md` 等。
- `store.library`、`store.groups`、`store.groupMapping`。
- 学者星穹需要的 `tags` 和 `progress_summary` 通过扩展 `TopicMeta` 在 `files:scan` 时返回，不新增 IPC。

**技术实现**
- 图表库：**ECharts graph**（推荐，React 集成简单，内置力导向、缩放、拖拽）。
- 数据准备：扩展 `TopicMeta`，增加 `tags: string[]` 和 `progress_summary?: string`，由 `files:scan` 在 init() 时一并返回。
- 关系计算：
  - 主规则：共享 tag。
  - 辅规则：标题/摘要关键词共现（TF-IDF 或简单词频）。
- 节点位置：ECharts force layout，无需后端计算。

**性能边界**
- ≤ 30 主题：流畅显示全部。
- 30–100 主题：轻微卡顿，默认过滤。
- > 100 主题：必须分页/过滤/采样。

**缓存策略**
- 全景图数据在 `init()` 时跟随 `library` 刷新而计算，不额外持久化。
- 学者星穹的 LLM 增强关系暂不实现，因此无需缓存。

**E2E 关注点**
- 进入 Profile 全景图页面能渲染。
- 书房概览四个统计数字正确。
- 学习节律热力图有数据点。
- 分组分布条形图与 Home 分组一致。
- 学者星穹节点数量正确，节点标签可见。
- 点击星穹节点导航到对应主题/PreStudy。
- 不测试图的精确布局（力导向非确定性）。

**风险**
- 学者星图实现复杂度高于其他三个模块，可能延期。
- 主题少（< 10）时星图空旷，需要考虑空状态/引导文案。
- E2E 断言困难，需要合理的 `data-testid` 策略。

### B4 学习记录副标题显示与编辑

**目标**
在 StudyLibrary 的会话列表中显示每份学习记录的具体方向副标题，并支持用户编辑。

**入口**
- `Home` 页面 → 展开主题 → 每个 session 行。

**字段决策**
- 沿用 `Frontmatter.description` 字段作为副标题。
- 理由：
  - `description` 已是 frontmatter 标准字段。
  - LLM 归档时已在 `<description>副标题</description>` 标签中生成 session 级摘要。
  - 现有报告已普遍包含该字段，无需数据迁移。
  - `ReportHeader.tsx` 已在报告详情页渲染该字段。

**数据流**
1. `getSessionMeta` 读取 `学习报告.md` 的 `frontmatter.description`。
2. `SessionMeta` 扩展 `description?: string`。
3. `files:scan` 返回的 `TopicMeta.sessions[]` 中每个 session 携带 `description`。
4. `StudyLibrary.tsx` 的 `SessionRow` 渲染"第N · {description}"；缺失时回退为"第N"。
5. 用户点击副标题进入编辑态，失焦或按 Enter 保存。
6. 保存时调用 `files:updateSessionDescription({ dirName, sessionNumber, description })`。
7. 主进程读取原文件 → 更新 frontmatter.description → 写回，不动 body。
8. 前端刷新 `library` 以显示新值。

**新增 IPC**
- `files:updateSessionDescription({ dirName: string; sessionNumber: number; description: string })` → `Promise<void>`

**状态结构**
- 扩展 `SessionMeta`：
  ```ts
  type SessionMeta = {
    // ...existing fields
    description?: string
  }
  ```

**错误处理**
- 读取 `description` 失败：静默忽略，按无 description 渲染。
- 保存失败：回退原值，toast 提示"副标题保存失败"。
- 空 description：允许保存为空，渲染回退为"第N"。

**E2E 关注点**
- 有 description 的 session 在 StudyLibrary 中显示"第N · {description}"。
- 无 description 的 session 只显示"第N"。
- 点击 description 可编辑，保存后刷新显示。
- 编辑失败时原值不变。
