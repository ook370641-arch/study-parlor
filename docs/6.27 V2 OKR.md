# Study Parlor V2 OKR（关键功能设计版）

> 本文档只记录 V2 的关键功能设计、范围边界、工作顺序和验收标准。
> 具体实现细节（状态结构、IPC、文件命名、错误处理、E2E 关注点）见配套文档 `docs/6.27 V2 OKR Implementation.md`。

---

## 1. 当前项目状态

- **V1 基础已稳固**：苏格拉底式夜话、自动归档、复习、分组管理、流程图、寓言、学习库扫描。
- **A 类功能代码已落地**：夜航简报、网络搜索、DIY 术语、作家语录、随机推荐均有对应页面/IPC/测试。
- **E2E 测试框架已搭好**：Playwright + CDP fixture，临时学习库/配置目录隔离。
- **B 类尚未实现**：内部资料读取、画作替换、用户画像、学习记录副标题显示与编辑。
- **C 类待决策**：本版 OKR 明确建议留到 V3。

---

## 2. V2 范围边界

**V2 包含：**
- A 类功能的细节补齐、UI/UX 打磨、完整 E2E 测试覆盖。
- B 类功能的方案设计与实现。
- 相关文档、类型、测试的同步更新。

**V2 不包含：**
- C 类功能（渐进式教案、课程体系、论文学习）。理由见第 6 节。

## 3. A 类：已引入功能（待 E2E 覆盖与收尾）

### A0 夜航简报

**目标**：每天生成一份 AI 行业日报，聚合 follow-builders 的 X/Podcast/Blog 内容，以双语 Markdown 形式缓存到学习库，并支持查看历史日报。

**入口**：`Cover` 页面新增入口，进入 `briefing` 页面。

**关键设计**：
- 默认展示当天日报；无缓存时调用 LLM 生成。
- 历史日报以侧栏形式展示，按日期倒序。
- V2 保持与学习页统一的极乐迪斯科风格；UI 升级移入 B 类。

---

### A1 网络搜索（外部资料）

**目标**：学习开始前，用户可选择启用网络搜索。AI 搜索并总结外部资料，作为上下文注入学习会话。

**入口**：`PreStudyModal` 中的"外部资料"勾选框。

**关键设计**：
- 基于 Tavily API 搜索，经 LLM 整理成导师备课笔记。
- 错误场景：未配置 key、网络失败、无结果、LLM 整理失败。
- 归档时生成"外部资料"文档。
- **E2E 策略**：Tavily API Key 独立加密存储；E2E 通过 `E2E_CONFIG_DIR` 隔离 credentials 目录，确保 `MISSING_API_KEY` 路径稳定可测。happy path 与网络相关错误路径走真实 Tavily + Kimi，标记 `@unstable`，本地按需跑。

---

### A2 DIY 术语

**目标**：用户可在扩展界面自定义应用字段/标签，影响各界面渲染，提高个性化。

**入口**：`extension` 页面。

**关键设计**：
- 支持 30+ 个术语字段，分四类：仪式动词、模式与流程、参数标签、界面名词。
- 修改后实时反映到 Cover/Home/Study/Profile/PreStudy。
- 自定义值持久化到 `state.json`，可一键恢复默认。
- **E2E 策略**：不调用 LLM，全部标记 `@smoke`。采用抽样测试：选取 5 个代表性字段（`sessionName`、`archiveVerb`、`difficultyLabel`、`homeGreeting`、`topicInputLabel`），验证 Extension 修改后同步到各页面、重启后持久化、重置后恢复默认。

---

### A3 作家语录

**目标**：在 Cover 页面与学习主页展示精选作家语录。

**入口**：`Cover` 右下角、`Home` 学习库底部、`Study` 页面。

**关键设计**：
- 196 条精选语录，页面加载时随机展示。
- 支持手动刷新。
- **E2E 策略**：`@smoke`，覆盖 Cover/Home/Study 三个 surface，验证语录非空、格式正确、刷新后仍有语录。

---

### A4 E2E 测试管线

**目标**：建立自动化测试，使得代码更改后可验证旧功能不被破坏，新功能可自主化调试。

**关键设计**：
- Playwright + 自定义 Electron fixture（spawn + CDP）。
- Page Object 模式：CoverPage、HomePage、PreStudyPage、StudyPage。
- 标记分层：
  - `@smoke`：不调用 LLM / 外部 API，约 5 秒，本地改完代码即跑。
  - `@slow`：调用真实 Kimi API，10 秒–2 分钟，验证 LLM 集成。
  - `@unstable`：依赖外部网络/feed/外部 API 或 LLM 输出不可预期，本地按需跑，不阻塞发布前验收。
- 每个用例使用独立临时学习库和配置目录；credentials 也通过 `E2E_CONFIG_DIR` 隔离。
- A 类功能测试覆盖：A0 夜航简报、A1 外部资料、A2 DIY 术语、A3 作家语录、A5 随机推荐。onboarding 与分组管理由其他窗口负责。

---

### A5 随机推荐（意外之径）

**目标**：在分组推荐中引入随机主题，给用户意料之外但相关的学习方向。

**入口**：`Home` 页面推荐卡片区域。

**关键设计**：
- 应用启动时若缓存为空，后台生成一次。
- 基于用户画像和学习历史，由 LLM 推荐跨学科主题。
- 支持手动刷新。
- **E2E 策略**：`@smoke` 通过预写 `state.json` 缓存验证卡片展示、点击带入 PreStudy、刷新按钮状态；`@unstable` 验证真实 LLM 生成与错误展示。

## 4. B 类：待实现功能

### B1 内部资料读取

**目标**：类似网络搜索，但使用用户本地文件作为学习上下文。

**入口**：`PreStudyModal` 中的"内部资料"勾选框，与"外部资料"并列。

**关键设计**：
- 支持与外部资料同时使用。
- 支持 `.md`、`.pdf`、`.txt`、常见代码文件；UI 显示支持格式列表。
- 选择本地文件后，复制到本次学习目录 `<主题目录>/sN/source/`，命名为 `内部资料-原文件名`，与外部资料归档文件区分。
- **资料备注（内部）**：勾选内部资料后，PreStudy 展开"使用方式"备注输入框，用户填写希望 AI 如何处理这些资料（如"我想了解这段代码实现的功能"）。备注与内部资料一起注入上下文。
- **资料备注（外部）**：与内部资料对称，勾选外部资料后也展开备注输入框，用自然语言描述使用意图与搜索倾向（如"重点补充哪些观点或背景""广泛搜索该领域最新动态""精确搜索少量经典博客或文献"）。备注同时参与搜索查询生成与摘要整理。
- 内外部资料备注均限制 500 字符，支持多行文本；默认值为空字符串，取消勾选期间保留已输入内容。
- V2 先不做摘要和文件大小限制，将内部资料全文及使用方式备注注入上下文。
- 单个文件失败时提示并跳过，其他文件正常加载。
- 归档生成独立的 `内部资料.md`。

---

### B2 画作替换

**目标**：更新应用背景画作，提升视觉体验。

**关键设计**：
- 以资源替换为主，代码只做必要展示调优。
- 替换 `Pictures/` 下表现不佳的画作。
- 不新增应用内画作管理功能。

---

### B3 用户画像（学者书房全景图）

**目标**：自动扫描学习库，为用户生成一幅只读的学习全景图，帮助用户看清自己的学习历史、习惯与知识分布。

**入口**：`Profile` 页面扩展，新增全景图入口（名称留待决策，如"全景图"或"学者星穹"）。

**关键设计**：
- **只读可视化，不做推荐**：避免与现有 `group-inspiration`、`wildcard`、`continue-topic` 推荐功能重叠。
- **四个可视化模块**：
  1. **书房概览**：主题总数、夜话总数、连续学习天数、最近学习时间。
  2. **学习节律**：GitHub contributions 风格热力图，展示每日学习活跃度。
  3. **分组分布**：按分组展示主题/session 分布。
  4. **学者星穹**：力导向知识星图，主题为星，共享 tag 的主题以星轨连接。
- **视觉风格**：延续极乐迪斯科暗色书房美学，把数据看板做成"天文馆/星象仪"质感。

---

### B4 学习记录副标题显示与编辑

**目标**：在 StudyLibrary 的会话列表中显示每份学习记录的具体方向副标题，并支持用户编辑。

**入口**：`Home` 页面展开主题后，每个 session 行。

**关键设计**：
- 沿用 `Frontmatter.description` 字段作为副标题，不新增字段，无需数据迁移。
- 扩展 `SessionMeta`，增加 `description?: string`，在 `files:scan` 时从 `学习报告.md` 读出。
- `SessionRow` 渲染为"第N · {description}"；无 description 时回退为"第N"。
- 支持用户点击副标题进入编辑，保存后通过新 IPC 更新报告 frontmatter，不改动正文。
- 编辑失败时回退原值并提示。

## 5. C 类：考虑是否纳入 V2 的功能

> 以下功能是否在 V2 中实现尚未拍板决定。基于复杂度与依赖关系，本版 OKR 建议均不纳入 V2，留待 V3。

### 5.1 渐进式披露的教案设计

**目标**：学习开始前预生成教案，避免"学到哪里算哪里"的随机感，让学生主动管理学习目标。

**理想流程**：
1. 用户决定是否引入外部搜索与内部资料。
2. AI 基于主题、画像、资料生成教案。
3. 与用户协商是否按此教案开始学习（此阶段内外部资料都进上下文）。
4. 用户确认后开始学习（上下文减少，只剩教案）。

**为什么不进 V2**：依赖网络搜索与内部资料读取先稳定；涉及新的会话阶段和 prompt 链。

### 5.2 课程体系搭建

**目标**：学习新领域时，AI 主动规划需要几个主题、几次学习，不是单 session 对话。

**涵盖场景**：
- **领域学习**：如经济学，协商确定学习列表。
- **书籍学习**：给 AI 一本书或让 AI 找电子书，协商拆分学习次数。
- **人物学习**：如马克思，协商主题与分段数量。

**入口疑虑**：是否需要在封面设置不同入口？

**为什么不进 V2**：体量最大，会改变核心会话模型；依赖用户画像和分组推荐。

### 5.3 论文学习

**目标**：针对主题推荐重要文章、博客、论文，并依据它们开展单对话学习。

**实现方式**：类似网络搜索准备外部资料，先聚合多篇文献再注入 session。

**入口疑虑**：PreStudy 增加选项 / 主题详情页按钮 / 单独模式。

**为什么不进 V2**：依赖搜索/文件读取的资料聚合能力；入口需更多验证。

### 5.4 决策：C 类均不纳入 V2

**决策：C 类三个功能均不纳入 V2，留待 V3。**

**理由**：
- 体量大，每个都涉及新会话模型、入口设计、LLM prompt 链。
- 依赖未清：教案依赖资料准备能力；课程体系依赖用户画像；论文学习依赖资料聚合。
- V2 已有足够内容：A 类 6 个 + B 类 4 个。
- 风险控制：放入 V2 会导致范围蔓延。

| 功能 | V2 状态 | 预计进 V3 的前提 |
|---|---|---|
| 渐进式披露的教案设计 | 跳过 | 内部/外部资料准备能力稳定后 |
| 课程体系搭建 | 跳过 | 用户画像、分组推荐、教案能力均成熟后 |
| 论文学习 | 跳过 | 网络搜索/文件读取的资料聚合能力稳定后 |
