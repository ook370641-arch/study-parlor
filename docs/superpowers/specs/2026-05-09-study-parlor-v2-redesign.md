# Study Parlor 第2次修缮设计文档

日期：2026-05-09
范围：文件结构重构 + 主页双模块 redesign

---

## 1. 问题陈述

### 1.1 文件结构混乱

现有三个平行文件夹（`学习/`、`寓言/`、`图片/`）管理同一批内容，导致：
- session 编号错位（报告标准学习 s1/s2/s5 对应寓言 s3/s4/s6）
- 图片归属混乱（`harness-engineering-research.png` 实际属于 vibe-coding）
- 主题归属错位（`Agent.png` 在 harness-engineering 目录下）
- 人工浏览时无法快速定位一次学习的完整文件

### 1.2 主页信息过载

当前主页为 3 列推荐卡布局（RecCard），信息层次不清，用户难以快速：
- 定位已有学习的历史记录
- 查看某次学习的完整产出（学习报告、寓言、图片）
- 继续或复习特定 session

## 2. 设计方案总览

### 2.1 核心决策

| 决策 | 选择 | 理由 |
|------|------|------|
| 文件结构 | 按主题聚合，每个 session 一个目录 | 人工浏览友好，程序索引简单 |
| 命名规则 | 统一中文描述性文件名 | 路径固定，无需解析变长文件名 |
| 对齐粒度 | per-session | 一次学习 = 一个学习报告 + 一个/多个寓言 + 图片 |
| 已有错位文件 | 重命名对齐，缺失留空 | 不生成缺失内容，保持历史真实性 |
| 旧文件夹 | 保留不动 | 应用后续只读 `学习库/`，不影响现有文件 |

### 2.2 不变的原则（MIGRATION.md）

- 产品逻辑在 `src/`，IO 在 `electron/`
- `src/lib/ipc.ts` 是唯一 facade
- 纯逻辑往 `src/lib/` 移

## 3. 文件结构迁移

### 3.1 新文件夹结构

在 `/工作与学习/` 下新建 `学习库/`：

```
学习库/
  {topic-dir}/
    s{session-number}/
      学习报告.md          # type: progress 的学习报告
      原始对话.md           # 会话完整聊天记录归档
      复习报告.md           # 每次复习单独保存，多次复习追加到同一文件
      寓言.md               # 主寓言文件
      寓言{n}.md            # 额外寓言文件（如 vibe-coding 有 2 个）
      学习配图.{ext}        # 不带 -research 后缀的图片
      寓言配图.{ext}        # 带 -research 后缀的图片
```

### 3.2 文件命名规则

| 文件名 | 说明 | 来源 |
|--------|------|------|
| `学习报告.md` | 学习报告（progress 模式产出） | 原 `学习/` 文件夹 |
| `原始对话.md` | 会话完整聊天记录 | **新增**：每次会话结束时保存 |
| `复习报告.md` | 复习记录 | 原追加到学习报告末尾 → 现在独立文件 |
| `寓言.md` | 主寓言文件 | 原 `寓言/` 文件夹 |
| `寓言2.md` | 额外寓言（同 session 多个） | 原 `寓言/` 文件夹 |
| `学习配图.{ext}` | 学习相关图片 | 原 `图片/` 中不带 `-research` 后缀的 |
| `寓言配图.{ext}` | 寓言相关图片 | 原 `图片/` 中带 `-research` 后缀的 |

### 3.4 迁移脚本

编写独立的 Node.js 迁移脚本（`scripts/migrate-library.js`），功能：

1. 读取 `学习/`、`寓言/`、`图片/` 三个源文件夹
2. 按上述映射表建立目标目录结构
3. 复制/重命名文件到新位置
4. 缺失项不生成，仅留空目录或跳过
5. 输出迁移报告（哪些文件已迁移、哪些缺失、哪些错位已修复）
6. **脚本只执行一次**，执行前提示用户确认

迁移完成后，修改 `.env` 的 `STUDY_LIBRARY_PATH` 指向新的 `学习库/` 目录。

## 4. 主页双模块 UI 设计

### 4.1 整体布局

删除现有的 3 列推荐卡（RecCard）逻辑，改为左右双模块：

```
+----------------------------------+
|  学者夜话          [设置] [头像]  |
+----------------------------------+
|                                  |
|  +----------+  +----------------+|
|  | 新学习   |  | 学习库         ||
|  |          |  |                ||
|  | [恢复]   |  | [Accordion]    ||
|  | [新建]   |  |                ||
|  | [推荐1]  |  |                ||
|  | [推荐2]  |  |                ||
|  | ...      |  |                ||
|  +----------+  +----------------+|
|                                  |
+----------------------------------+
```

### 4.2 左侧「新学习」模块

#### 4.2.1 上次未完成的对话（恢复提示）

- 启动时检测 `state.json` 中是否有未完成的 session
- 如果有，显示：
  ```
  上次对话：报告标准（进行中）  [继续]  [丢弃]
  ```
- 点击「继续」→ 恢复 session 进入 Study 页面
- 点击「丢弃」→ 删除未保存的 session 记录

#### 4.2.2 开始新学习

- 大号按钮：「+ 开始新学习」
- 点击后进入预学习流程（选择主题/模式/难度）

#### 4.2.3 推荐学习主题

- 垂直列表，3-5 个推荐主题
- 每项格式：
  ```
  [图标]  主题名
         推荐理由（一行）
  ```
- 点击后进入该主题的预学习流程
- 推荐逻辑复用现有的 `inspirations` 机制（`NewTopic[]`）
- 删除现有的 `RecCard` 推荐逻辑

### 4.3 右侧「学习库」模块

#### 4.3.1 整体结构

- 单列 Accordion 列表，所有主题垂直堆叠
- 默认全部折叠
- 顶部显示统计：「共 N 个主题 · M 次学习」

#### 4.3.2 主题头部（折叠状态）

```
报告标准                    [继续学习（第四次）]  ▼
3 次学习 · 上次学习：11 天前
```

- 主题名（左）
- 「继续学习（第 N 次）」按钮（右），N = 当前 session 数量 + 1，点击进入下一次学习
- 展开/折叠箭头（右）
- 副标题：session 数量 + 相对时间（几天前）

#### 4.3.3 展开后的 Session 列表

每个 session 一行：

```
s1 · 2026-04-01    ✓ 已复习    [学习报告] [原始对话] [复习报告] [寓言] [图片]
s2 · 2026-04-27    ✕ 未复习    [学习报告] [原始对话] [开始复习] [寓言] [图片]
s3 · 2026-04-28    ✕ 未复习    [学习报告] [原始对话] [开始复习] [寓言] [图片]
```

**字段说明：**
- 左侧：session 编号 + 日期 + 复习状态标签（✓ 已复习 / ✕ 未复习）
- 右侧：5 个按钮，固定字段对齐
  - `学习报告` — 打开学习报告 modal
  - `原始对话` — 打开原始对话 modal
  - `复习报告` — 有复习时显示，打开复习报告 modal
  - `开始复习` — 无复习时显示，进入复习模式
  - `寓言` — 打开寓言 modal
  - `图片` — 打开图片预览
- 缺失项：按钮禁用态（灰色不可点），不隐藏

**颜色方案（橙色系）：**
- 「开始复习」：橙边框 + 橙字，hover 橙底黑字
- 「复习报告」：褐底 + 浅橙字，hover 橙底黑字
- 已复习标签：橙色高亮

**按钮排版：**
- 四字按钮拆成 2x2：学习\n报告、原始\n对话、复习\n报告、开始\n复习
- 两字按钮保持单行：寓言、图片
- 统一高度对齐

#### 4.3.4 5 个按钮的打开方式

所有按钮点击后打开**应用内 modal/抽屉**，不调用外部程序：
- `.md` 文件：用 Markdown 渲染组件显示
- `.png/.jpg`：用图片预览组件显示
- modal 有关闭按钮，可点击外部关闭

## 5. 新增功能

### 5.1 原始对话归档

**触发时机：** 每轮消息完成后追加写入临时文件，会话正常结束后重命名为正式文件。

**文件格式：** Markdown

```markdown
# 原始对话

## 2026-05-09 14:30:15
**用户**：...

---

## 2026-05-09 14:30:30
**AI**：...

---
```

**实现细节：**
- 会话期间写入 `{session-dir}/原始对话.md.tmp`
- 会话正常结束（finalize）后重命名为 `原始对话.md`
- 应用崩溃时，`.tmp` 文件保留，下次启动可检测并提示恢复

### 5.2 会话恢复

**持久化：**
- 每次消息状态变更后，通过 `ipc.patchState` 将当前 session 的 `messages` 数组保存到 `state.json` 的 `unsavedSessions` 字段
- 已有 `UnsavedSession` 类型和 `restoreSession`/`removeUnsavedSession` 机制

**恢复检测：**
- 启动时（`init()`）检测 `unsavedSessions`
- 如果有，在左侧「新学习」模块显示恢复提示

### 5.3 复习报告独立存储

**变更：** 复习记录不再追加到原学习报告末尾，而是单独保存为 `复习报告.md`。

**实现：**
- 修改 `finalize.ts` 中的 review 模式处理逻辑
- 原文件：在学习报告末尾追加复习段 + 更新 frontmatter
- 新文件：写入 `{session-dir}/复习报告.md`，同时更新 frontmatter

### 5.4 会话结束时自动生成寓言

**触发：** 会话正常结束（progress 模式）后，调用 LLM 生成寓言。

**流程：**
1. 用户点击「结束会话」
2. 调用 LLM 提取标题 + 正文 → 写入 `学习报告.md`（现有逻辑）
3. **新增**：调用 LLM 生成寓言 → 写入 `寓言.md`
4. **新增**：把完整对话历史写入 `原始对话.md`

**注意：** 图片不自动生成，需要用户手动添加。

## 7. 数据模型变更

### 7.1 Frontmatter 扩展

```typescript
interface Frontmatter {
  title: string
  session_number: number
  created: string        // ISO date
  last_studied: string   // ISO date
  review_count: number
  difficulty: 'low' | 'mid' | 'high'
  tags: string[]
  type: 'progress' | 'review' | 'research'
  progress_summary?: string
  // 新增字段
  has_fable?: boolean      // 是否有寓言文件
  has_image?: boolean      // 是否有学习配图
  has_fable_image?: boolean // 是否有寓言配图
  last_reviewed?: string   // 上次复习时间（ISO date）
}
```

### 7.2 TopicMeta 扩展

```typescript
interface TopicMeta {
  dirName: string          // 主题目录名
  title: string
  sessionCount: number     // session 数量
  sessions: SessionMeta[]  // 每个 session 的元数据
  last_studied: string     // 最近学习时间
  last_studied_days: number // 相对天数（几天前）
}

interface SessionMeta {
  sessionNumber: number
  date: string
  hasReport: boolean
  hasTranscript: boolean
  hasReview: boolean
  hasFable: boolean
  fableCount: number       // 寓言文件数量
  hasImage: boolean
  hasFableImage: boolean
}
```

## 8. 错误处理

### 8.1 文件缺失

- 缺失项在 UI 上显示为禁用态按钮，不隐藏
- 用户知道"这个 session 缺了什么"

### 8.2 迁移失败

- 迁移脚本输出详细报告
- 不删除源文件，只复制到新位置
- 用户可以手动检查并修复

### 8.3 会话恢复失败

- 如果 `.tmp` 文件损坏，提示用户"上次对话可能不完整"
- 提供「丢弃并新建」选项
