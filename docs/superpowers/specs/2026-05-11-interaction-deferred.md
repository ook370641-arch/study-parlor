# 交互设计 · 本轮跳过清单

> 本轮（2026-05-11 全套交互设计）中因频率过低而跳过的交互。记录在此，待后续轮次激活。

---

## 跳过项

### A1 · Cover → Home 首入动效

- **触发频率**：一生一次（首次输入名字后）
- **跳过原因**：投入产出比极低。首入动效虽然情感重量高，但用户永远不会第二次看到。
- **建议后续处理**：
  - 方案 A：不处理，保持瞬间跳切。首屏的核心价值是快速进入，不是动画。
  - 方案 B：如果品牌需要，可制作一段 3-5 秒的启动视频/开机动画，仅在首次播放。
- **激活条件**：产品做品牌宣传片、或发现首入流失率异常高时。

### B1 · Cover 名字输入 — 初次见面的仪式

- **触发频率**：一生一次
- **跳过原因**：同 A1，一生一次的交互不值得本轮投入。
- **建议后续处理**：当前简单 input + 按钮已足够功能性。若后续要增加 onboarding 体验，可在此处加入引导文案。
- **激活条件**：产品增加 onboarding 流程、或做用户引导优化时。

### E2 · 流式错误横幅

- **触发频率**：低频（仅在 LLM 流式传输失败时触发）
- **跳过原因**：错误状态应保持功能性优先。当前红色横幅 + 关闭按钮已足够清晰。过度设计错误状态可能让用户困惑。
- **建议后续处理**：保持现有实现。错误状态的视觉风格应与整体 UI 保持一致（避免突兀的红色），但不需要额外的动效。
- **激活条件**：错误发生率显著上升、或用户反馈错误提示不够友好时。

### E3 · 致命启动错误页

- **触发频率**：一生一次（希望如此）——仅在 .env 配置错误时触发
- **跳过原因**：这是应用的「救护车」，不是「礼宾车」。功能性是第一位的。当前酒红色标题 + 配置说明已足够引导用户修复问题。
- **建议后续处理**：保持现有实现。确保错误信息足够具体（哪个配置项错了、怎么修）。
- **激活条件**：发现用户在错误页卡死、或错误信息不够清晰时。
