# 健身跟踪（夜航简报第三来源）设计文档

日期：2026-10-08
状态：已批准（visual companion 四轮迭代定稿）

## 1. 需求汇总

来源：封面迭代记事板第 5 点 + 2026-10-07/08 两轮对话澄清。

- **定位**：记录工具，不是打卡。没有"今日待练"、streak、提醒；用户隔几周记一次，零维护压力
- **目标**：长期跟踪训练重量变化与身体尺寸
- **三个核心对象**：计划（相对固定）/ 记录（一笔一笔）/ 趋势（记录的投影）
- **用户假想链路**：记录计划（一周五练 · 三个动作序列）→ 记录单日数据 → 进入页面查看历史训练情况 → 下方趋势图
- **UI 出口**：夜航简报来源竖栏第三位「健身」，`data-testid="briefing-source-icon-fitness"`

明确否决的 early 方案：四 tab（今日/趋势/历史/计划）冗余；「现在」可编辑标签与「记录当下」职责重叠；逐次训练打卡式录入成本过高。

## 2. 数据模型

存储：`~/.studyparlor/fitness.json`（独立文件，不进 state.json —— 记录持续增长，state.json 是配置型状态）。带 `version` 字段，损坏时备份 `.bak` 重建默认（复用 safe-json 模式），写入走临时文件 + rename 原子写。

```ts
type FitnessData = {
  version: 1
  /** 动作序列（默认 推/拉/腿 三个，可增删改名） */
  routines: FitnessRoutine[]
  /** 周安排：一周几练 = 数组长度；weekday 1..7 */
  schedule: { weekday: number; routineId: string }[]
  /** 逐组快照，追加制，id 幂等 */
  records: FitnessRecord[]
  /** 身体尺寸，按日期 upsert */
  bodyMetrics: BodyMetric[]
}

type FitnessRoutine = {
  id: string
  name: string                    // 「推」「拉」「腿」或自定义
  exercises: FitnessExercise[]
}

type FitnessExercise = {
  id: string
  name: string
  sets: number                    // 组数 —— 唯一持久化的训练参数
}

type FitnessRecord = {
  id: string                      // 日期 + 随机，防重/删除用
  date: string                    // YYYY-MM-DD
  routineId: string               // 当时练的序列（历史快照，序列改名不影响）
  entries: {
    exerciseId: string
    sets: { weight: number; reps: number }[]   // 二维数组：逐组 重量×次数
  }[]
}

type BodyMetric = {
  date: string                    // 同日再记 = 覆盖
  weight?: number                 // kg
  chest?: number; waist?: number; hip?: number
  arm?: number; thigh?: number    // cm，全选填
}
```

关键决策：

- **重量不持久化在计划里**。计划只存 动作 + 组数；重量只存在于记录中。"上次记录"永远从最近一笔记录派生，不是独立状态
- **记录当下不碰计划**：保存记录 = 新增一条 record，routines/schedule 不动
- **改计划不改历史**：组数/动作/序列的修改只影响以后记录的格子数，已存 record 永远保持原样
- **趋势按动作名聚合**：同名动作出现在不同序列，合并为一条线
- 动作从计划删除后，其历史记录不删：历史快照照常显示，趋势选择器仍列出该动作
- 首次运行默认：序列 推/拉/腿（各 4-5 个常见动作）；周安排 周一推 / 周三拉 / 周五腿

## 3. UI 结构

健身面板 = 两面一切换（左上角轻量 seg，非重 tab）+ 一个独立计划管理面。折线图组件两处复用。

### 3.1 重量面 · 落地态（默认）

- 进入即见**最新一笔记录**（只读）。无「现在」标签
- 顶栏：左「重量 / 尺寸」seg + 「⚙ 计划」；右 记录标签列（`‹` `9/3` `9/28` `10/27` `›`）+ 「✎ 记录当下」
- 状态行：日期 · 序列名 · 距上一笔 N 天
- 三栏（按序列分栏）：本笔所属序列琥珀点亮、展示该笔逐组格子；其余序列淡显各自**最近一次**记录供对照，列尾标注其日期。点淡显序列列头 = 切到该序列最近一笔
- 底部折线图（见 §4）
- 历史查看三条路：标签列 / `‹ ›` 前后翻 / 点折线上的点；当前查看日期在折线上带描边光晕

### 3.2 重量面 · 记录态

- 点「✎ 记录当下」进入：顶部变为「● 正在记录 {今天日期} · 保存快照 / 取消」
- 默认带出**今天周几对应的序列**（schedule 推导；今天是休息日则默认最近一次记录的序列），可切换成任意序列（计划练推今天练了腿）
- 该序列每个动作展开为**组格子横排**：组数 = 计划里的 sets，每格上重量下次数，预填该序列上一笔记录的值；改过的格子琥珀描边；某组没练可去掉该格，也可临时加格（只影响本笔，不回写计划）
- 「保存快照」→ 新 record 追加，标签列末尾出现新标签，回到落地态（显示刚存的这笔）

### 3.3 尺寸面

- 左栏「记一次 · {今天日期}」表单：体重 + 胸/腰/臀/臂/腿，全选填，同日再记覆盖
- 右侧**历史表格**：每行一个日期、六列指标、没记显 `—`、最新在上、行尾 `×` 删除
- 表格下方折线图：指标 chips（体重/腰围/胸围/…）切换
- 与重量面完全独立，只共享折线组件

### 3.4 计划管理面（⚙ 入口）

- 周安排：一行七格（一~日），每格显示所挂序列或「休」，点击切换序列
- 序列编辑栏：每序列一列，动作名 + 组数（虚线下划线 = 可编辑），「＋动作」「＋新序列」、序列改名
- 底部承诺文案：「改组数/动作/序列只影响以后的记录格子，已存的历史记录永远保持原样」

### 3.5 视觉语言

遵循 ui-styling §11：夜色底 `#2a1f1a` + 米色衬线 `#e8d5b7` + 琥珀 `#d97757` 仅用于激活态/记录动作/折线端点。无动画（纯静态渲染，天然满足 prefers-reduced-motion）。组格子、快照标签、seg 均为细边圆角小件，不引入新装饰语言。

## 4. 折线图规格（手写 SVG，零依赖）

- 数据稀疏是常态：2 个点也画一条线；0 个点显示空态文案；1 个点只画点
- 重量面：选中动作的每笔记录取**第一组重量**（做组重量）为 y 值，点上标注 `{weight} × {reps}`
- 尺寸面：选中指标的值
- 样式：米色折线（opacity .75）+ 琥珀端点圆点 + 淡网格 + y 轴自适应刻度 + x 轴稀疏日期
- 交互：点圆点 = 切到那天的记录（重量面）/ 无（尺寸面）
- 选择器 chips：有记录的动作名（重量面）/ 有记录的指标（尺寸面）

## 5. IPC 与分层

新域 `electron/ipc/fitness.ts`，按 types → handler → preload → facade → store 五层同步（general §2）：

- `fitness:load` → FitnessData（缺失则初始化默认并落盘）
- `fitness:saveRecord`（id upsert，幂等）/ `fitness:deleteRecord`
- `fitness:saveBodyMetric`（date upsert）/ `fitness:deleteBodyMetric`
- `fitness:savePlan`（routines + schedule 整体写，仅计划管理面调用）

无网络/LLM 调用，全部即时返回，无需 AbortController。store 侧新增 `fitness` slice，视图状态（当前查看的记录 id、选中序列、记录态草稿）留在组件内，不入持久化。

## 6. 验收清单

- 空数据（首次使用）：默认序列+周安排初始化，重量面显示空态引导（「还没有记录，点 ✎ 记录当下」）
- fitness.json 损坏 → `.bak` 备份 + 默认重建，应用不崩
- 跨重启持久化：记录/尺寸/计划改完重启原样回显
- 同日多笔记录各自独立；同日尺寸覆盖不叠加
- 删记录后折线正确收敛；删到 0 笔显示空态
- 计划改组数后：新记录格子数变化，旧记录格子数不变
- 折线 0/1/2 点不崩；单点不画线
- e2e：来源竖栏第三位入口可见可点（`briefing-source-icon-fitness`）、记录一笔后重载仍在、尺寸记一次后表格出现新行；更新 `e2e/source-map.json`
- 全局 Chrome 检查（ui-styling §8/§9）：来源竖栏、背景层、主题切换在健身面下正常

## 7. 测试计划

- 单元（`tests/fitness.test.ts`）：fitness.json 解析/校验/损坏恢复、默认初始化、record upsert 幂等、bodyMetric 按日期 upsert、折线数据派生（每动作首组重量提取、动作名跨序列合并）
- 组件：落地态/记录态/空态渲染，记录态预填逻辑
- e2e 定向：`e2e/fitness.spec.ts` + source-map 登记
- 无 LLM/网络依赖，全部确定性 mock，无需真实 API 回归路径
