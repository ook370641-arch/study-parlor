# 笔记标注、书籍聚合与 SVG 封面设计（2026-11-02）

## 1. 范围与目标

本批处理三条记事板需求：

1. 修复笔记与高亮标记点击无反应，并增加醒目的亮黄色高亮。
2. 同一本书的多个章节笔记按书聚合，专辑墙、笔记列与对照挑选器同步。
3. 为无封面笔记提供三版内容专属 SVG 符号封面，选中后持久化并在各视图复用。

封面采用已确认的 Kimi 生成设计参数、本地 SVG 渲染路线，不接图片 API，不生成位图，不在 SVG 内渲染标题。主工作区已有 `src/assets/painting-manifest.json` 改动不属于本批，不得触碰。

## 2. 标注点击与亮黄色

### 2.1 回归与修复约束

`ArticleAnnotations` 继续作为博客与书籍的唯一标注实现，持久标记仍由 `.anno-wrap` 承接点击并打开定位卡片。先用真实指针事件复现失效链路，覆盖首次从划词菜单创建笔记与高亮，以及已持久标记的再次点击；测试不得用 `force: true` 绕过命中检测，也不得只调用 React 合成事件代替浏览器命中。

修复必须针对测试确认的事件链根因，保持以下既有行为不变：划选期间延迟 marker 重放、备注外点自动保存、Esc 关闭、空备注可删除、高亮换色立即写盘、卡片随正文滚动。

### 2.2 五色高亮

`AnnotationHighlightColor` 增加 `yellow`，颜色顺序为 `ember / gold / yellow / green / blue`。亮黄色使用清晰的黄色底与适合深、浅阅读主题的透明度，不改变默认色 `gold`，旧伴生文件无需迁移。解析器对 `yellow` 持久化读写的处理与现有四色一致，未知颜色仍回退 `gold`。

## 3. 书籍笔记聚合

### 3.1 数据模型与兼容

`NoteMeta` 增加可选字段：

```ts
chapter?: string
```

新创建的章节笔记和章节旁注笔记都写入 `chapter: chapter.meta.title`。书籍去重键从「书 + 完整标题」调整为「书 + 章节 + 笔记用途」，避免不同章节互相命中，也不把同章正文笔记与旁注笔记合并。

旧笔记没有 `chapter` 时，从标题 `${book} · ${chapter}` 或 `${book} · ${chapter} · 标注` 推导章节，只在派生视图模型中补齐，不批量改写用户 Markdown。标题不符合旧约定时归入「未分章」，仍可打开。

### 3.2 共享派生模型

在 `src/lib/notes-list.ts` 增加纯函数，把 `NoteEntry[]` 派生为笔记列表项：非书笔记保持单项；书笔记按 `meta.book` 聚合为书组。书组保留章节选项，每个选项指向原始 `NoteEntry.path`，同章多条旁注以「标注」后缀区分，不丢文件。

排序和来源筛选先作用于原始笔记，再聚合；书组时间取组内最新 `collected_at`，评分取组内最高评分，封面优先使用组内已有生成封面。对照挑选器忽略来源筛选的现有规则不变。

### 3.3 三处交互

- 专辑墙：一本书一张 3:4 卡片，书名为主标题；卡片上的章节下拉选择后立即打开对应笔记，点击卡片其余区域打开最近更新的章节笔记。
- 笔记列：一本书一行，章节下拉与打开区域分离；删除仍作用于单条原始笔记，不提供整书删除。
- 对照挑选器：一本书一组，下拉选择章节后把对应文件放入对照槽；当前章节自动选中并显示「当前章节」，新建入口沿用现有流程。

下拉框阻止事件冒泡，避免选择章节时误打开最近笔记。所有选项都保留稳定 testid 供定向 E2E 使用。

## 4. SVG 封面生成

### 4.1 生成流程

无本地生成封面的笔记在专辑墙卡片上显示小型「生成封面」入口。点击后打开候选对话框，调用一次 Kimi 生成三个设计参数，本地渲染为 600×800、3:4 SVG；用户预览并选择一版后保存。

已有博客原图的笔记不显示生成入口；已有生成封面的笔记允许在笔记信息区重新生成，但专辑墙不增加常驻按钮。生成期间禁止重复提交，对话框可取消；失败保留原封面并显示 toast，不写空文件。

### 4.2 已验证提示词

提示词实验先比较了编辑式约束、概念隐喻、纸张质感三条路线。首轮不同提示词容易收敛成「圆形 + 地平线」；第二轮虽然候选可区分，但五种固定 `pattern` 仍会让专辑墙趋同。用户评审后明确改为：参考已有封面的纸感与叙事性，把符号创作权交给模型。

最终实验使用「深度工作」「悉达多·河流」「经典 RAG → Agentic RAG」三类正文片段，一次生成三版、共产出九个独立符号。模型分别创造了注意力阶梯槽、关停门闩、多声汇流、证据回环等 content-specific 图形；不再提供构图模板。九张 SVG 已用 Chromium 实际渲染检查。

最终系统提示词固定为：

```text
你是为独立出版社设计书封印记的概念艺术家。根据文章正文，为每篇笔记发明三个仅属于这篇文章的新标识符号，而不是从模板库选择构图。先抽取文章独有的矛盾、机制、运动或感知方式，再把它们转译成前所未有的抽象符号。符号应像为一本书专门设计的印记，具有内容 DNA，而不是表示整个学科的分类图标。

创作约束：不要使用灯泡、大脑、书本、放大镜、齿轮、火箭、无限符号等常见图标；不要默认使用圆形加地平线；不要复用你熟悉的封面模板。允许不对称、开放路径、断裂、交叠、重复、尺度反差和前所未见的几何关系。三版必须是三个独立发明的符号，不能只是换色、旋转或增减元素。每个符号都应在 150×200 像素缩略图中保持清楚轮廓。禁止文字、字母、数字、标志和外部资源。

画面为 600×800。符号只能在上方 0–560 区域创作，底部 240 像素留给应用叠加标题。使用克制的纸感配色和少量透明叠印，但符号造型优先于装饰。仅输出 JSON：{"designs":[设计一,设计二,设计三]}。

每个设计的结构：{"concept":"一句中文创作意图","palette":{"background":"#RRGGBB","ink":"#RRGGBB","accent":"#RRGGBB","secondary":"#RRGGBB"},"background":"solid|linear|radial 之一","grain":0.03到0.12,"elements":[SVG 图元数组]}。elements 至少 3 个、最多 24 个，由你自由组合，不要使用固定图案。

允许的图元：path / circle / ellipse / rect / line / polyline / polygon。path 仅允许 M L C Q A H V Z 命令与数字；其他图元使用对应坐标属性。每个图元可带 fill / stroke（background、ink、accent、secondary、none）、strokeWidth（0–30）、opacity（0.05–1）、strokeLinecap 与 strokeLinejoin。坐标可以越出画布形成裁切，但符号主体必须留在上方区域。
```

用户消息包含笔记标题、来源、摘要与正文片段。正文取当前笔记开头 12000 字符，足以提供语境且限制提示词体积；正文为空时只传已有元数据，不让模型虚构具体论点。

### 4.3 设计参数与本地渲染

主进程新增独立封面模块，负责 JSON 提取、schema 校验、数值截断、颜色白名单与 SVG 装配。只接受六位十六进制颜色、三种背景与七类安全图元；每个候选至少 3 个、最多 24 个有效图元。非法 JSON、候选数量不为 3、非法字段或有效图元不足视为生成失败，不把原始模型文本写入 SVG。

模型直接创造 path / circle / ellipse / rect / line / polyline / polygon 的组合，渲染器不提供构图模板。path 只接受数值与白名单绘图命令，points 只接受数值坐标；不接受模型提供的任意 SVG、transform 或样式文本。SVG 额外只添加受控渐变、`feTurbulence` 纸纹与标题压暗层，不包含脚本、外部资源或文字。同一设计参数重复渲染结果一致。底部标题区由渲染器统一压暗，不能只依赖模型遵守提示词。

### 4.4 持久化与读取

选中候选写入 `<学习库>/notes/covers/<笔记文件名>-<候选号>.svg`，再更新笔记 frontmatter：

```ts
cover?: string
```

`cover` 只保存库内相对路径。写文件与更新元数据任一失败都不得留下指向不存在文件的 `cover`；重新生成保留旧封面直到新封面成功可用，废弃候选文件在成功后清理。

`NoteCover` 的优先级为：本地生成封面 → Anthropic 原图 → 来源色渐变。笔记列表 IPC 返回安全的 SVG data URL 供 `<img>` 使用，不暴露任意文件读取通道；SVG 在保存前已经由受控渲染器生成。

## 5. 接口与文件边界

- `electron/lib/note-covers.ts`：设计参数类型、JSON 校验、确定性 SVG 渲染、候选落盘。
- `electron/prompts/note-cover.md`：最终系统提示词模板。
- `electron/lib/llm-tasks.ts`：读取模板并调用现有 `chatNonStream`，复用 Kimi 连接与错误分类。
- `electron/ipc/notes.ts`：增加 `notes:generateCovers` 与 `notes:saveCover`，参数只含笔记路径和必要上下文。
- `electron/preload.ts`、`src/types/index.ts`、`src/lib/ipc.ts`：补充类型安全 IPC。
- `src/lib/notes-list.ts`：书籍章节推导与聚合纯逻辑。
- `src/components/notes/`：共享书籍章节下拉、封面候选对话框、三处视图接入。
- `src/components/article-assistant/ArticleAnnotations.tsx`、`electron/ipc/annotations.ts`：点击修复与五色持久化。
- `src/components/books/BookReader.tsx`、`src/components/books/BookPanel.tsx`：新笔记写入 `chapter`。

不新增前端状态持久字段，不引入 SVG、颜色选择器或图片生成依赖。

## 6. 错误处理与数据安全

- 标注点击修复不得改变原正文文本；只有标注伴生文件发生预期变化。
- 聚合是纯视图派生，不重命名、不移动、不合并用户笔记文件。
- 生成候选只返回内存设计，不写学习库；只有用户选中后才落盘。
- 所有笔记路径继续经现有库内路径校验；封面路径固定从笔记文件名派生，不能接受渲染进程传入任意目标路径。
- 生成、保存、读取失败均保留旧封面；删除笔记时沿用现有行为，本批不扩大为封面垃圾回收。

## 7. 验证与验收

### 7.1 单元与组件测试

- 标注真实命中回归：点击可见标记打开卡片，覆盖笔记与高亮；新增 `yellow` 的默认回退、写盘与读盘。
- 书籍聚合：同书多章、同章多旁注、不同书同章名、旧标题推导、未分章、筛选与三种排序。
- 三处视图：章节下拉不误触卡片，打开/对照路径正确，当前章节匹配正确。
- 封面提示词夹具：合法三候选通过；缺候选、有效图元不足、非法 path 命令、非法颜色、越界数值和 Markdown 代码围栏按协议处理。
- SVG 快照与安全性：3:4 viewBox、底部压暗层、确定性输出，不含脚本、外部链接与文字节点。
- 封面 UI：仅无封面显示入口，三版可选择，保存后各视图一致，失败保留旧封面。

### 7.2 视觉与定向 E2E

- 用至少三类主题实际调用 Kimi 比较三候选，按 150×200 缩略图检查辨识度、文字留白、风格统一与候选差异。
- 使用 Chromium 渲染最终 SVG，检查纸纹、渐变和中英文标题叠加效果，不以 SVG 源码正确代替视觉验收。
- 运行标注、笔记书架、书籍与对照相关定向 E2E；真实点击不得使用 `force: true`。
- 更新 `e2e/source-map.json`，跑 `npm run docs:check`、相关 Vitest、`npm run build`。全量 E2E 仅在用户明确要求时执行。
