1. 问题概览：配额消耗全景

核心问题

当前求职简报（Job Briefing）每次生成消耗 约 35-40 次 Tavily API 调用。以 Tavily Researcher 免费套餐（1000 次/月）计算，每天跑一次就用光月配额。E2E 测试中同样调用真实 Tavily，进一步加剧配额消耗。

按默认配置（10 家关注公司），单次 generateJobBriefing 的 Tavily 调用分布：

阶段Tavily 调用LLM 调用说明
① discoverEvents（发现新动态） 11 11 10 家公司各 1 次搜索 + 1 次汇总搜索
② discoverOfficial（发现官方招聘页） 最多 20 0 每家公司 2 个查询（中文 + 英文），成功即停

2. Tavily 是什么？（零基础说明）

一句话概括

Tavily 是一个专为 AI Agent 设计的网络搜索引擎 API。你把搜索词发过去，它返回相关的网页标题、URL 和内容摘要——跟 Google 搜索类似，但是为程序调用优化的。

关键概念

概念含义本项目的设置
API Key身份凭证，每个请求都要带存在 ~/.studyparlor/ 加密存储
Credit（配额）每次调用消耗的点数免费套餐 1000 credits/月
search_depth搜索深度：basic（1 credit）或 advanced（2 credits）当前用 basic ✅
max_results每次返回最多几条结果3~8 条不等
days只搜最近 N 天的内容7~90 天不等
include_domains只搜指定网站如 nowcoder.com（牛客网）

本项目的 Tavily 封装

所有 Tavily 调用都经过 electron/lib/search.ts 的 searchWeb() 函数：

export async function searchWeb(opts: TavilySearchOptions): Promise<TavilyResult[]> {
  const res = await fetch(url, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      api_key: opts.apiKey,
      query: opts.query,          // 搜索词
      search_depth: 'basic',     // 基础深度（1 credit/次）
      max_results: opts.maxResults ?? 5,
      include_answer: false,
      ...(opts.days ? { days: opts.days } : {}),
      ...(opts.includeDomains?.length ? { include_domains: opts.includeDomains } : {})
    })
  })
  // ... 错误处理 ...
  return data.results  // → [{ title, url, content, score }]
}

4. 调用策略详解：求职简报五阶段

阶段 ① discoverEvents — 发现招聘新动态 11 次 Tavily

buildEventQueries()
生成 11 个搜索词 → 循环 11 次
逐个调 Tavily → 每次结果 → LLM
提取事件 JSON → 过滤 + 去重 + 排序

当前搜索词生成逻辑（buildEventQueries）：

export function buildEventQueries(config: JobBriefingConfig): EventQuery[] {
  const cities = config.cities.join(' ')
  // 每家公司一个搜索词
  const queries = config.companies
    .filter(c => c.enabled)
    .map(c => ({
      query: `${c.name} 2026秋招 2027届 校招 宣讲会 AI产品 招聘 ${cities}`,
      company: c.name
    }))
  // 加一个汇总搜索
  queries.push({
    query: `AI产品 2026秋招 2027届 校招 汇总 ${cities}`,
    includeDomains: ['nowcoder.com', 'yingjiesheng.com']
  })
  return queries  // → 11 个查询
}

Tavily 调用参数：maxResults: 5, days: 7

问题：10 家公司串行搜索，每个结果还要调一次 LLM 提取。串行 + 数量多 = 又慢又贵。

阶段 ② discoverOfficial — 发现官方招聘页面 最多 20 次 Tavily

当前搜索词生成逻辑（buildOfficialPageQueries）：

export function buildOfficialPageQueries(company: string): string[] {
  return [
    `${company} 官方招聘 AI产品经理`,      // 中文查询
    `${company} careers AI product manager`, // 英文查询
  ]
}

调用逻辑（discoverCareerPage）：

for (const query of queries) {
  const results = await searchWeb({ query, maxResults: 3 })
  const official = results.find(r =>
    r.url.includes('jobs.') || r.url.includes('careers.') ||
    r.url.includes('zhaopin') || r.url.includes('join')
  )
  if (official) return { url: official.url }  // 找到就停
}
注意：这段代码的返回值 在当前主流程中未被使用！generateJobBriefing 直接跳过了 discoverCareerPage，优先用预配置的 careerPageUrl，只有在没有预配置时才走 Tavily。但 discoverCareerPage 仍在导出，可能在 UI 层或其他地方被调用。

阶段 ③ 岗位搜索 — 为焦点公司搜索具体岗位 3~5 次 Tavily

当前搜索词生成逻辑（buildFocusJobQuery）：

export function buildFocusJobQuery(company, profile, config): string {
  const roles = profile.targetRoles.length ? profile.targetRoles : config.roleKeywords
  const cities = config.cities.join(' ')
  return `${company} ${roles.join(' ')} 招聘 校招 2026 ${cities}`
}

Tavily 调用参数：maxResults: 5, days: 30

然后对 每个搜索结果 再调一次 LLM（extractJobsFromHtml）提取结构化岗位信息。如果 3 个焦点公司各返回 5 条结果 = 15 次 LLM 调用。

阶段 ④ discoverQuestions — 发现面经高频问题 最多 4 次 Tavily

当前搜索词生成逻辑（buildQuestionQueries）：

export function buildQuestionQueries(focus, profile, config): QuestionQuery[] {
  const direction = profile.direction || config.roleKeywords[0]
  return focus.slice(0, 3).map(f => ({
    query: `${f.name} ${direction} 面经 面试题`,

Tavily 调用参数：maxResults: 5, days: 90

Fallback（前面全失败时）：${direction} 面经 高频问题

搜索词的问题分析

问题 1：搜索词冗余

每条搜索词都把"2026秋招 2027届 校招 宣讲会 AI产品 招聘 北京 上海 杭州 深圳"全塞进去，导致：

  • 搜索词过长（>100 字符），Tavily 官方建议 不超过 400 字符——虽然没超标，但冗余关键词稀释了核心意图
  • 10 家公司的搜索词高度雷同，返回结果可能大面积重叠

问题 2：重复搜索同一主题

如果字节和阿里同时开了秋招，牛客网上同一篇文章可能被两家公司的搜索都命中——这就是 10 次搜索产生大量重复结果的原因。

问题 3：串行执行

discoverEvents 用 for...of 逐个调 Tavily，11 次请求串行执行 = 等待时间长且无法利用 Tavily 的并发能力。

6. Tavily 官方最佳实践

核心原则（来自 Tavily 官方文档）

  1. 搜索词精炼：像写给搜索引擎的搜索词，不是写 prompt。400 字符以内。
  2. 复杂问题拆成子查询：一个宽泛问题拆成 2-3 个聚焦子查询，效果优于一个长查询
  3. 并行执行：用 Promise.allSettled 同时发多个请求，而非串行
  4. 结果去重：不同查询可能返回相同 URL，去重后再往下游处理
  5. 控制搜索深度：basic（1 credit）通常够用，不要默认 advanced（2 credits）
  6. 领域过滤：用 include_domains 缩小搜索范围，提高精度
  7. 时效过滤：用 days 参数限制时间范围
  8. 两步法：Search → 过滤评分 → Extract（只对高相关结果做深度提取）

7. 优化方案：新调用策略 + 新提示词

优化目标

将求职简报的 Tavily 调用从 ~40 次 → ~6-8 次（降低 ~80%），同时不丢失信息覆盖度。

策略 A：合并搜索词 → 按层级批量搜索

核心思路：不再按"每家公司一个搜索词"，而是按"信息层级"分类搜索。

❌ 旧方案：每家搜一次

10 个搜索词，串行执行：
"字节跳动 2026秋招 校招..."
"阿里巴巴 2026秋招 校招..."
"腾讯 2026秋招 校招..."
...（共 10 个）
+ 1 个汇总搜索词
= 11 次 Tavily

✅ 新方案：按信息源分层

3 个搜索词，并行执行：

第 1 层 — 社区汇总贴（限域）
"2026秋招 2027届 校招 AI产品 大模型
提前批 汇总"
→ include_domains: nowcoder.com,
   yingjiesheng.com
→ 1 次 Tavily

第 2 层 — 全网动态（不限域）
"2026秋招 AI产品经理 校招开启
字节 阿里 腾讯 百度 美团 MiniMax
智谱 月之暗面"
→ days: 7
→ 1 次 Tavily

第 3 层 — 宣讲会/线下活动
"2026秋招 AI 校招 宣讲会
线下 北京 上海 杭州 深圳"
→ days: 14
→ 1 次 Tavily

合计：3 次（↓73%）
为什么 3 个搜索词就够了？
  • Tavily 的 maxResults 可以调到 10-15，3 个搜索词 × 10 条结果 = 30 条结果，覆盖度足够
  • 搜索词里包含所有公司名，一条结果可能覆盖多家公司
  • 社区汇总贴（牛客网）天然就是多家公司的合集
  • LLM 提取阶段按公司分类即可——从 30 条结果里挑出各公司的动态，比从 50 条分散结果里挑更高效

策略 B：去掉 discoverOfficial 的独立 Tavily 调用

❌ 旧方案

每家公司 2 个搜索词：
"${公司} 官方招聘 AI产品经理"
"${公司} careers AI product manager"
→ 最多 20 次 Tavily

✅ 新方案

方案 B1（推荐）：完全移除 Tavily 搜索。
改为在"岗位搜索"阶段的结果中
顺带识别官方招聘页 URL。
→ 0 次额外 Tavily（↓100%）

方案 B2（备选）：如果确实需要单独搜，
合并为一个搜索词：
"${公司} 官网招聘入口 careers jobs"
→ 仅对无预配置 careerPageUrl 的公司使用
→ 0~2 次
为什么可以移除？当前代码中 discoverCareerPage 的返回值在 generateJobBriefing 主流程中实际未被使用——主流程优先用预配置的 careerPageUrl。如果某公司没预配置，岗位搜索阶段搜到的结果里自然包含该公司的招聘链接。

策略 C：岗位搜索合并 + 结果聚合

❌ 旧方案

每个焦点公司单独搜：

策略 E：并行化 + 去重

当前：串行 for...of

for (const q of buildEventQueries(config)) {
  const results = await searchWeb({ query: q.query, ... })
  // 处理 results...
}

11 次 Tavily 调用串行 → 即使每次 1.5s，总耗时 ~16.5s

优化后：并行 Promise.allSettled

const queries = buildEventQueries(config)  // 精简后只有 3 个
const settled = await Promise.allSettled(
  queries.map(q =>
    searchWeb({ query: q.query, apiKey, maxResults: 10, days: q.days, signal })
  )
)
// 收集所有成功的结果
const allResults = settled
  .filter(r => r.status === 'fulfilled')
  .flatMap(r => r.value)

// 去重 URL
const seen = new Set<string>()
const unique = allResults.filter(r => {
  const key = r.url.replace(/\?.*$/, '')
  if (seen.has(key)) return false
  seen.add(key)
  return true
})

3 次 Tavily 调用并行 → 总耗时 ~2s（↓88%）

9. 实施建议

推荐的实施顺序

  1. 第一步（最快见效）：合并搜索词 + 并行化。
    改动范围：buildEventQueries / discoverEvents。
    效果：Tavily 调用 11→3，总耗时 ~16s→~2s。
  2. 第二步：移除 discoverOfficial 的独立 Tavily 调用。
    改动范围：generateJobBriefing 主流程。
    效果：Tavily 调用最多再减 20 次。
  3. 第三步：合并岗位搜索 + 批量 LLM 提取。
    改动范围：岗位搜索循环 + extract-jobs.md prompt（支持多公司）。
    效果：Tavily 调用 3~5→1，LLM 调用 15~25→1。
  4. 第四步：合并面经搜索。
    改动范围：buildQuestionQueries + aggregate-questions.md prompt。
    效果：Tavily 调用 4→1。

注意事项
