# AI 笔记两轮检索与单文件生成设计

日期：2026-11-05

阅读体验修订：2026-11-08

## 1. 背景与目标

博客与书籍章节已支持一次性 AI 笔记生成。首轮真实使用表明，现有产物虽然信息充分，但缺少理解入口，语言也过度学术化；用户即使只读一段，仍需自行翻译抽象术语并拆解多重从句。本轮优化把目标从“提高认知密度”改为：**即使用户已经忘记原文和上次阅读背景，重开笔记后也能迅速恢复理解，再按需读到深度。**

最终形态是“先读懂，再读深”。“钻石＋展柜”只保留为内部内容筛选比喻，不得作为正文标题或读者需要理解的表达：

- **理解入口**：开篇先用概要说明本文在回答什么问题、核心答案是什么、关键矛盾在哪里；不让读者先穿过作者资历、理论源流或研究背景。
- **核心内容**：保留来源全文的核心命题、关键区分、主论证与结论，不搬运正文，不逐节复述，不详细展开案例。
- **思想脉络**：核心思想读懂之后，再选择真正有帮助的理论关系、批评与适用边界；外部资料不得抢占主线。
- **个人连接**：原笔迹决定叙述重心，并在相关位置自然回应用户的真实关注点；需要修正时说明理由，但不写成“印证／修正／延伸”的论文评语。

正文目标仍为约 1000–1400 中文字，最多 1600 中文字，按内容自然组织 3–5 个部分，使用短段落、分点、编号或小标题。不得为了达到字数堆叠背景、资历、理论分支或重复总结。长度按正文汉字数验收，不把英文来源列表计入。

### 1.1 已确认的实验结论

同一章节分别测试不联网、一轮检索、两轮检索。最终采用两轮方案，但不是把原始搜索结果直接堆入写作提示词，而是：

`多查询宽域扫描 → 基于结果进行多查询脉络深钻 → 资料策展 → 笔记写作 → 措辞优化`

早期二轮版曾因“550–750 字、最多两条思想关系”的限制丢弃全部第二轮引用。根因不是第二轮资料未进入输入，而是长度约束过强且缺少检索策展。最终管线先提取两轮各自的有效思想关系，再写作；引用数量本身不作为质量指标。

### 1.2 用户场景与阅读需求

| 场景 | 用户状态 | 必须满足的需求 |
|---|---|---|
| 生成后第一次读 | 刚读完来源，但没有整理出主线 | 开篇直接给出问题、答案和核心矛盾，而不是再次复述来源背景 |
| 隔一段时间重开 | 已忘记原文、作者和上次阅读上下文 | 只读标题、开篇概要和各节标题，30 秒内恢复“这篇笔记在讲什么” |
| 快速回顾 | 只有片刻时间，想找回关键判断 | 不读来源列表和原笔迹附录，也能抓住核心区分与结论 |
| 有时间深读 | 希望理解为什么，以及观点何时不适用 | 在读懂主线后，仍能读到因果链、关键区分、适用边界、思想脉络和个人连接 |

阅读体验按以下标准验收：

1. **开篇可独立理解**：第一部分必须是概要或关键概念解释，先回答“问题—答案—矛盾”，再进入论证。不得以来源介绍、作者资历或理论定位开场。书籍章节在章节名、导读或正文足以判断时，用一句话交代本章在全书中的作用，例如“序言负责说明为何需要这个框架，而非展开完整方法”；无法判断时不编造。
2. **概念不预设背景**：影响主线理解的专业概念第一次出现时，用日常语言解释；若单靠定义仍不直观，补一个短例子。不能为了显得专业而保留可替换的术语。
3. **句子只推进一层意思**：一个句子只承担一个主要判断或一层关系；多重转折、因果和限定应拆成短句。每段只回答一个问题，优先使用具体动词和直接表达。
4. **标题帮助回忆**：标题直接写出本节的问题或结论，不使用“钻石”“展柜”“思想坐标”“核心蒸馏”等内部工艺词。
5. **简明不等于只给结论**：不得删掉使观点成立的关键区分、理由、因果链和适用边界。深度来自把关系解释清楚，而不是来自术语、引用数量或单句信息量。
6. **个人连接自然可读**：回应原笔迹中真实存在的问题，不重复引用原笔迹，不为了完成“印证／修正／延伸”的动作而写学术评语。

### 1.3 非目标

- 不创建独立 AI 笔记文件，不保留多个 AI 版本。
- 不提供重新生成、批量生成、自由聊天或通用研究报告。
- 不删除原笔记，不把来源原文复制进笔记。
- 不为缺少导读的旧内容额外生成导读；有导读则必须使用，无导读不阻断。
- 不改变现有博客／章节「生成对应笔记」的创建或打开语义。

## 2. 入口与交互

### 2.1 统一生成标识

生成入口使用现有图标风格的 **Sparkles 四芒星 SVG 图标按钮**，不使用「AI 蒸馏笔记」文字按钮。无障碍名与悬停提示均为“生成笔记”。状态如下：

- 可生成且空闲：显示可点击四芒星。
- 生成中：显示旋转进度图标，按钮禁用。
- 已成功生成：不再显示生成按钮，也不提供重新生成入口。

### 2.2 主笔记编辑器

入口放在 `NoteMetaHeader` 的头部操作区。笔记须满足：

1. 是 `notes/*.md` 中可正常解析的笔记。
2. `meta.ai_generated_at` 不存在。
3. 来源为可解析到本地正文的博客（`anthropic` / `web`）或书籍章节（`book`）。

主编辑器只依据元数据显示入口；真正生成时主进程再次解析来源，来源不存在则返回错误，不创建空结果。

### 2.3 对照页

`ArticleCompanionBoard` 的对照头部显示同一四芒星入口。除上述条件外，对照笔记必须与当前主文精确匹配：

- 博客：笔记 `meta.url` 与当前文章规范化后的 `source_url` 相等。
- 书籍：`meta.source === 'book'`，且 `meta.book` 与当前书名一致，`noteChapter(entry)` 与当前章节一致。
- 当前对照为普通文章、仓库文件、其他博客／章节笔记、只读内容或空槽时不显示。

在对照页生成后直接刷新当前对照笔记，不跳页、不切换主文、不新建文件。主编辑器和对照页共享同一生成状态与持久标记，任一入口成功后另一入口立即消失。

### 2.4 生成与确认

1. 点击图标后，先等待当前主笔记或对照笔记的脏内容保存完成。
2. 主进程锁定笔记路径并检查持久标记，随后展示读取材料、第一轮检索、第二轮检索、资料策展和写作进度。
3. 完成后显示生成正文预览；此时尚未修改笔记文件。
4. 用户确认“写入笔记”后，主进程一次性写入 AI 正文、原笔迹附录和 `ai_generated_at`。
5. 取消预览只丢弃候选；失败或取消均允许重试。只有成功写入才构成“已生成”。

## 3. 数据契约与来源装配

### 3.1 持久元数据

`NoteMeta` 新增：

```ts
ai_generated_at?: string // 成功写入 AI 笔记的 ISO 时间；永久防重标记
```

`parseNoteFile` 识别该字段；其他 frontmatter 原样保留。无需新增 `state.json` 字段。

### 3.2 笔记输入

每次生成装配：

```ts
type AiNoteInput = {
  notePath: string
  title: string
  sourceText: string
  guideText: string | null
  originalNote: string
  sourceIdentity: { type: 'blog'; url: string } | { type: 'book'; book: string; chapter: string }
}
```

- 博客优先通过 `.collection.json` 的 `entries/read` 将 URL 映射到 `filePath`，再以 `Anthropic博客/**/*.md` 的 `source_url` 精确匹配兜底。
- 书籍通过 `books/<书>/book.json` 的章节标题定位 `chapterFile`，读取章节正文；所有路径继续经受学习库边界校验。
- 对应 `<来源>.guide.md` 存在且可解析时，使用其正文作为 `guideText`；缺失或损坏时传 `null`，不另起导读生成管线。
- `originalNote` 是当前笔记正文。传入模型前剔除内嵌 Base64 图片并保留 `[内嵌图片]` 占位；磁盘原内容不作清洗或改写。
- 同一笔记不会二次生成，因此不存在把旧 AI 正文再次作为输入的链路。

## 4. 两轮检索与写作管线

新增 `electron/lib/note-ai-generation.ts` 负责模型编排，`note-ai-source.ts` 负责来源与导读装配。复用 `chatNonStream`、`searchWeb`、`getSearchApiKey` 和 JSON 提取能力。

### 4.1 第一轮：思想宽域定位

规划器接收标题、导读、原笔迹和正文，生成 2–3 个简短英文查询，覆盖理论源流、相邻理论、关键分歧与批评。禁止搜索案例细节、名言出处、操作教程或产品清单。查询并行调用 Tavily，按 URL 去重。

### 4.2 第二轮：思想脉络深钻

规划器接收相同笔记材料与第一轮结果，沿用点亮灯火的“从结果识别子维度再深钻”模式，生成 2–3 个精准英文查询。只补足概念源流、相邻框架关系、主要批评或适用边界，不转向案例扩写。

### 4.3 资料策展

策展模型接收正文导读、原笔迹和两轮资料，输出 3–5 条内部思想坐标素材：关系类型、核心判断、如何修正或深化原文、来源编号。要求合并重复来源、剔除营销内容与案例细节，并检查第二轮是否提供首轮没有的独特关系；没有独特增益时如实保留空结果，不伪造使用。

下游写作只接收策展结果与紧凑的来源编号表，不再接收几十条原始搜索摘要。这样第二轮资料先被评估，再参与篇幅分配。

### 4.4 笔记写作与措辞优化

写作提示词遵循：

- 正文是事实与论证依据；导读提供结构；原笔迹提供关注主线与明确连接；策展素材提供思想坐标。
- 全文精华不等于逐节摘要，主动牺牲覆盖率以换取理解效率，但不得少到只剩结论卡片。
- 开篇先交付“问题—答案—核心矛盾”；关键概念随用随解释，必要时用短例子建立直觉。
- 书籍章节在材料足够时用一句话点明本章在全书中的作用，不展开目录介绍，不编造前后章节关系。
- 例子只写帮助理解或证明论点所必需的部分，不展开无关过程、数字与产品清单。
- 自然回应原笔迹中的真实关注点，需要修正时给出理由，不使用学术评语腔。
- 自然组织 3–5 个部分，每节只回答一个问题；标题直接写出问题或结论，一句只推进一层意思。
- 联网事实保留 `[W1-1]` / `[W2-1]` 编号，末尾只列实际引用来源。
- 模型只输出 AI 正文与必要来源，不输出原笔迹附录、frontmatter、写作说明或代码围栏。

写作先产生完整初稿，随后由独立措辞优化调用降低表达门槛。该调用只接收初稿，不重新检索或改写研究结论；复用 `writing` 进度阶段，不增加界面状态。

措辞优化后的正文汉字数少于 900 或超过 1600 时，沿用措辞优化要求执行一次篇幅修订；仍不合格则不写入笔记，返回生成失败并保留重试入口。

## 5. 提示词文件与职责

新增五个独立模板，避免检索规划、资料策展、写作与措辞优化互相污染：

- `electron/prompts/note-ai-round1.md`：宽域定位，只寻找理论来源、相邻理论、关键分歧与批评。
- `electron/prompts/note-ai-round2.md`：根据第一轮结果识别思想子维度，深钻源流、关系、批评与边界。
- `electron/prompts/note-ai-curate.md`：从两轮资料中策展 3–5 条高价值关系，保留来源编号，明确第二轮独特增益。
- `electron/prompts/note-ai-write.md`：按本规格的理解入口、通俗表达、深度、长度、原笔迹连接和引用约束生成 AI 正文。
- `electron/prompts/note-ai-polish.md`：只优化完整初稿的开篇、概念解释、句子与标题，保持论点、深度和真实引用。

写作模板的稳定核心为：

```text
先让读者迅速读懂，再让读者按需读深。笔记必须能在忘记原文和阅读背景时独立打开。

正文提供事实与论证，导读提供结构，原笔迹提供思考起点与连接点，
策展素材提供思想坐标。全文精华不等于逐节摘要。

开篇先写问题、核心答案和关键矛盾；关键概念第一次出现时用日常语言解释。
自然组织 3-5 个部分，每节只回答一个问题，一句只推进一层意思。
标题直接写出本节问题或结论，不使用“钻石／展柜／思想坐标”等内部工艺词。
自然回应原笔迹的真实关注点，需要修正时说明理由，不写成论文评语。
例子只保留帮助理解或证明论点所必需的部分。
只使用真正有认知价值的思想关系，不以引用数量为目标。

只输出 AI 正文与实际引用来源，不输出原文、原笔迹附录、复习题、
行动清单、写作说明、frontmatter 或代码围栏。
```

## 6. IPC、候选预览与原子写回

### 6.1 IPC

新增类型与通道：

```ts
type AiNoteStage = 'reading' | 'round1' | 'round2' | 'curating' | 'writing'
type AiNoteProgress = { generationId: string; path: string; stage: AiNoteStage }
type AiNoteCandidate = { generationId: string; path: string; body: string }

notesGenerateAi({ path }): Promise<AiNoteCandidate>
notesApplyAi({ generationId }): Promise<{ path: string; body: string; aiGeneratedAt: string }>
notesAbortAi({ generationId }): Promise<void>
onNotesAiProgress(callback): Unsubscribe
```

主进程保存候选会话：`generationId → { path, baseRawHash, aiBody }`。路径锁从生成开始持有到写入、取消或失败，防止两个入口对同一笔记并发生成。已存在 `ai_generated_at` 时直接返回 `ALREADY_GENERATED`，不得启动搜索或模型调用。

### 6.2 写回格式

确认写入时再次读取文件并计算 raw hash：

- 与生成前快照不同：返回 `NOTE_CHANGED`，不覆盖用户的新编辑，候选失效并释放锁。
- 已有 `ai_generated_at`：返回 `ALREADY_GENERATED`，不重复写入。
- 校验通过：以当前 frontmatter 为基础加入 `ai_generated_at`，保留未知字段，组合正文后通过临时文件＋重命名原子替换。

非空原笔迹的最终结构：

```md
[AI 生成正文与其实际引用来源]

---

## 原笔迹

[生成前的完整笔记正文，逐字保留]
```

原笔迹为空时不添加空附录。附录使用生成前 gray-matter 解析出的原始 `content`，不做 `trim`、图片清洗或 Markdown 规范化；这些处理只作用于模型入参副本。AI 模型不得自行生成上述分隔与附录，拼接只由主进程完成。

### 6.3 渲染状态同步

生成前必须等待当前编辑器的 dirty 保存完成，避免自动保存覆盖生成结果。写入成功后：

- 刷新 `notesList`，使两个入口同时依据 `ai_generated_at` 消失。
- 若 `writingFile.path` 等于目标路径，更新其正文与保存状态。
- 若 `articleCompanion.filePath` 等于目标路径，更新对照正文、dirty 与保存状态，不卸载当前对照。
- 清理候选与路径锁；生成失败、取消或来源变化时保留原文件与重试能力。

## 7. 错误处理与降级

- 未配置 Tavily：返回 `MISSING_API_KEY`，不进入写作。
- 单个搜索查询失败：容忍并保留同轮其他结果；任一整轮完全失败则本次生成失败，不静默降级为不联网或一轮版。
- 查询规划或策展输出非法：允许重试一次；仍失败则终止并释放锁。
- 来源正文无法定位、为空或越出学习库：返回 `SOURCE_NOT_FOUND` / `SOURCE_INVALID`，不写文件。
- 导读缺失或损坏：以 `guideText: null` 继续，不因此改变入口资格。
- 长度一次修订后仍不合格：返回 `NOTE_GENERATION_INVALID`，不写文件。
- 预览期间文件被外部或其他编辑器修改：返回 `NOTE_CHANGED`，优先保护新编辑。
- 最终写盘失败：原文件保持原样，不设置 `ai_generated_at`，界面保留重试入口。

## 8. 文件边界

- `electron/lib/note-ai-source.ts`：博客／章节解析、导读读取、原笔迹模型入参清洗。
- `electron/lib/note-ai-generation.ts`：两轮查询、并行搜索、资料策展、写作、措辞优化与长度修订。
- `electron/lib/notes.ts`：新元数据解析、候选合并与原子写回纯逻辑／IO。
- `electron/ipc/notes.ts`：候选会话、路径锁、三个 IPC 与进度事件。
- `electron/preload.ts`、`src/lib/ipc.ts`、`src/types/index.ts`：类型安全 API。
- `src/lib/note-ai.ts`：主笔记与对照场景的入口资格纯逻辑。
- `src/components/notes/AiNoteGenerator.tsx`：四芒星入口、进度、预览与确认／取消。
- `src/components/notes/NoteMetaHeader.tsx`、`src/components/article-assistant/ArticleCompanionBoard.tsx`：两个入口接入。
- `src/store/index.ts`：保存前置、生成动作与写回后的双编辑器状态同步。
- `e2e/source-map.json`：登记新模块和 `notes-ai-generation.spec.ts`。

## 9. 验证与完成标准

### 9.1 单元与组件测试

- 博客 URL 规范化与文件定位、书籍书名＋章节定位、导读存在／缺失、Base64 图片清洗。

### 9.3 完成定义

- 同一篇笔记最多成功生成一次，跨入口、重启和并发均成立。
- AI 正文独立可读、结构清晰、长度适中，能联系原笔迹并提供思想脉络。
- 冷读验收：不回看来源、不查术语，只读标题、开篇概要和各节标题，30 秒内能复述本文问题、核心答案和关键矛盾。
- 深度验收：读完正文能解释核心概念、关键区分及其理由；不能靠删去边界、因果链或反例来换取简短。
- 表达验收：正文不以作者资历或理论定位开场，不出现“钻石／展柜”等内部工艺标题，不用连续的抽象名词与多重从句制造理解门槛。
- 真实产物验收：至少使用《Intercom on Jobs-to-be-Done · Foreword》的同份材料重新生成并通读；若单轮写作仍出现明显官腔或开篇门槛，再评估独立的措辞优化节点，不预先增加管线复杂度。
- 原笔迹逐字保留，任何失败路径不损坏或删除原文件。
- 博客与书籍、主编辑器与对照页行为一致；无隐藏的一轮／不联网降级。
