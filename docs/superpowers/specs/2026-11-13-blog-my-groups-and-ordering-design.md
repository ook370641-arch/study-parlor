# 博客「我的」分组、筛选与共享排序设计

日期：2026-11-13

交互原型：已由用户验收通过。本文同时记录现有博客逻辑审计结果，实施时不得以新版布局为由删除既有能力。

## 1. 背景与目标

当前 Anthropic 博客页的第二列同时承载收藏、已读、推荐入口、来源筛选和全部文章，专辑墙又与第二列共用筛选状态。已保存但尚未读、也未收藏的文章没有明确归属，手动顺序也无法保存。

本次改造目标：

1. 第二列与专辑墙都提供「我的 / 全部」一级标签，筛选状态彼此独立。
2. 「全部」内使用来源二级标签；「我的」内的所有分组也支持同一套来源筛选。
3. 「我的」同时展示「已保存 / 已读 / 收藏」三个分组，不在分组间切换。
4. 三个分组均可折叠、可调整分组顺序；分组内文章也可手动排序。
5. 两侧筛选与折叠互不影响，但分组顺序和组内文章顺序共享并持久化。
6. 保留推荐、导入、阅读、删除、对照和异常恢复等现有逻辑。

## 2. 非目标

- 不为「全部」提供手动排序；仍按发布日期排序。
- 不允许文章跨分组拖拽；分组归属仍由保存、已读和收藏操作决定。
- 不修改推荐算法、推荐生成输入或推荐批次内容。
- 不重构阅读器、旁注、对照、笔记或书籍模块。
- 不自动清理或合并旧数据中的已读／收藏重叠记录。

## 3. 状态模型与分组归属

### 3.1 三个分组

- **已保存**：文章文件仍存在（`isSaved && filePath`），且不在已读或收藏中。
- **已读**：存在于 `blogCollection.read`。
- **收藏**：存在于 `blogCollection.entries`。

已读和收藏仍按现有规则互斥：新发生的收藏操作会移出已读，新发生的已读操作会移出收藏。旧数据若已经重叠，不迁移、不静默删除，仍按各自记录显示；「已保存」始终排除任一标记存在的文章。

文章文件被删除但其他标记仍保留时，继续沿用现有语义：对应已读／收藏条目可继续显示，打开失败时执行现有清理或重新导入逻辑；不得因为文件不存在而把文章错误加入「已保存」。

### 3.2 共享顺序

持久化四套顺序：

- `groups`：三个分组的顺序，默认 `['saved', 'read', 'favorite']`。
- `saved`：已保存文章的 URL 顺序。
- `read`：已读文章的 URL 顺序。
- `favorite`：收藏文章的 URL 顺序。

第二列与专辑墙读取同一份顺序。任意一侧完成拖拽后，主进程保存并返回完整 collection，两侧立即使用同一结果刷新。折叠状态和两侧筛选状态不共享。

## 4. 页面结构与交互

### 4.1 一级与二级筛选

第二列和专辑墙各自维护：

- `view`：`mine | all`。
- `source`：`all` 或一个来源 key。

「全部来源」为默认来源标签，来源单选，不再沿用多来源组合筛选。切换一侧的「我的 / 全部」或来源不得改变另一侧。

- 「全部」：显示来源二级标签；专辑墙保留「最新发布 / 最早发布」，第二列继续按最新发布排列。
- 「我的」：显示同一组来源二级标签，并同时过滤已保存、已读、收藏三个分组。
- 第二列搜索只过滤第二列，不影响专辑墙。
- 内置宪法报告仅进入「全部 → 全部来源」，继续置顶，不进入「我的」。

筛选与排序状态保持现有的会话内状态，不新增持久化。

### 4.2 分组标题与折叠

每个分组标题行包含拖拽手柄、折叠按钮、组名和数量。三组的折叠按钮在两侧都存在：

- 折叠只隐藏本侧该组内容，另一侧保持原状。
- 折叠状态为运行时状态，刷新后恢复展开。
- 折叠后仍可通过标题拖拽调整分组顺序。
- 第二列保留现有的分组高度调整能力；调整后不影响另一侧。

### 4.3 分组拖拽

拖动分组标题的拖拽区调整 `groups` 顺序，放下后两侧同步。分组拖拽与文章拖拽使用不同的拖动类型，互不触发。

### 4.4 文章卡片与列表行

- 只有悬停时显示的拖拽手柄可以启动文章排序。
- 卡片或列表行的其余区域继续执行打开／导入，不得因为点击正文而排序。
- 操作按钮继续执行自己的动作，不触发打开或拖拽。
- 文章只能在当前分组内排序；拖到其他分组时不产生变化。
- 来源筛选或搜索生效时，只显示匹配文章，但拖拽仍重排完整顺序中的相对位置：拖到某个可见目标前／后，即相对该目标移动；隐藏文章不丢失，且隐藏文章彼此的相对顺序不变。拖到空白区域不改变顺序。
- 全部视图不支持文章拖拽。

### 4.5 推荐入口的位置

「推荐记录」和「重新推荐」位于**收藏分组标题行正下方、收藏卡片上方**，第二列与专辑墙一致：

- 收藏折叠时两个入口一起隐藏。
- 收藏展开时显示，无论当前收藏筛选结果是否为空。
- 「我的」中的其他分组和「全部」不显示推荐入口。
- 推荐生成期间继续显示阶段与取消入口。

## 5. 文章生命周期与保留逻辑

所有标记变化都同时更新两侧视图和对应顺序。除新一轮推荐批量入夹外，新进入某组的文章默认置于该组首位，已有文章的自定义顺序保持不变。

| 操作 | 结果 |
|---|---|
| 导入未保存文章 | 保存文件并进入「已保存」首位；点击导入期间继续支持进度展示和按 URL 取消 |
| 打开已保存文章 | 沿用阅读器或对照槽路由，不改变分组 |
| 标记已读 | 进入「已读」首位，移出「收藏 / 已保存」；推荐来源加入 `dismissed` |
| 取消已读 | 移出「已读」；文件仍保存且未收藏时回到「已保存」首位，不自动恢复收藏 |
| 收藏 | 进入「收藏」首位，移出「已读 / 已保存」 |
| 取消收藏 | 移出「收藏」；文件仍保存且未读时回到「已保存」首位 |
| 已保存文章取消导入 | 沿用「取消导入」确认并删除文章文件，移出「已保存」 |
| 已读卡片移出 | 沿用「移出已读并删除」确认，移出已读并删除文章文件 |
| 收藏卡片移出 | 沿用「移出收藏并删除」确认，移出收藏并删除文章文件；推荐来源同时加入 `dismissed` |
| 阅读器切换已读／收藏 | 与列表和专辑墙使用同一 store action，立即反映到分组 |
| 删除文章文件 | 保留现有“其他标记保留”语义，并关闭正在阅读的同文件阅读器 |
| 打开时发现文件丢失 | 保留现有提示、标记清理或重新导入行为 |
| 删除推荐批次 | 只删除该批历史，不动当前收藏、已读或 dismissed |
| 新一轮推荐完成 | 保留手动收藏、已读和 dismissed；已有顺序保留，新推荐收藏追加到收藏顺序末尾 |

推荐页、推荐理由展开、推荐批次徽标、推荐备注、推荐记录固定入口及推荐完成后的右侧推荐页均保持现有行为。

## 6. 数据持久化与兼容

沿用 `<学习库>/Anthropic博客/.collection.json` 和现有安全写入，不新增第二份事实源。`BlogCollectionFile` 增加可选字段：

```ts
order?: {
  groups: BlogMineGroup[]
  saved: string[]
  read: string[]
  favorite: string[]
}
```

`BlogMineGroup = 'saved' | 'read' | 'favorite'`。旧文件没有 `order` 时按以下规则派生：

1. 分组顺序使用 `saved → read → favorite`。
2. 已读沿用现有 `read` 数组顺序。
3. 收藏保留手动收藏在前、推荐收藏在后的现有顺序。
4. 已保存按发布日期倒序派生。

加载及每次变更后执行顺序校正：去重、移除已不再属于该组的 URL、补入缺失 URL、修复非法分组名。不得改写 `entries`、`read`、`history` 或 `dismissed` 的业务含义。

排序 IPC 只接受合法分组名、已知 URL 和去重后的数组。写入失败时返回错误，渲染进程恢复拖拽前顺序并提示保存失败，不得只更新界面而伪装成持久化成功。

## 7. 模块调整

- `src/lib/section-filter.ts`：将共享的 Mine/All/多源状态机拆成独立的 `mine/all` 与单来源筛选状态。
- `src/lib/blog-groups.ts`：新增纯逻辑，负责分组派生、顺序校正、过滤后重排和状态流转所需的顺序更新。
- `src/components/anthropic/AnthropicBlogPanel.tsx`：持有两侧独立筛选、折叠和高度状态，向两侧传入同一 collection 与排序动作。
- `src/components/anthropic/BlogWall.tsx`：渲染我的三组、全部视图、分组标题、推荐入口和手柄拖拽。
- `src/components/anthropic/BlogCollectionSection.tsx`：按新布局承载第二列我的分组；保留推荐对话框、理由、操作按钮和高度调整。
- `src/components/anthropic/AnthropicArticleRow.tsx`：复用现有打开、导入、收藏、已读和取消导入行为。
- `electron/lib/blog-collection.ts`：读取旧数据、校正并保存共享顺序。
- `electron/ipc/anthropic.ts`、`electron/preload.ts`、`src/types/index.ts`、`src/lib/ipc.ts`：增加一个带类型校验的排序 IPC，返回更新后的完整 collection。
- `src/store/index.ts`：提供统一排序 action，并让所有现有标记操作复用最新顺序。

学术版与报纸版共用逻辑，操作按钮、标签、空态和弹窗分别使用现有主题样式。

## 8. 保留的外围行为

以下能力与布局改造无关，但必须继续工作：

- 新文章检测、刷新提示和栏目级错误重试。
- 第二列整体折叠及折叠后的缩略图 rail。
- 已保存边框、导入动画、加载与空态。
- 阅读位置、上次阅读恢复、对照槽恢复及写作对照挑选器。
- 文章导读、旁注、标注、对应笔记和内置宪法交互报告。
- 图片降级、旧来源色签、长标题悬停展开。

## 9. 验收与测试

### 9.1 纯逻辑测试

- 旧 collection 无 `order` 时正确派生，异常顺序去重并修复。
- 已保存、已读、收藏归属正确；新操作互斥，旧重叠数据不被静默改写。
- 导入、取消标记、取消导入、移出并删除、推荐更新后的顺序正确。
- 来源过滤后的文章重排只改变目标相对位置，隐藏项不丢失。
- 分组排序与文章排序互不影响。

### 9.2 定向交互回归

- 两侧「我的 / 全部」和来源筛选互不影响；来源过滤覆盖三个我的分组。
- 三组合折叠独立；推荐入口位于收藏标题下方并随收藏折叠。
- 分组顺序、每组文章顺序在两侧同步，重启后保留。
- 只有手柄可拖拽；点击卡片其他区域仍打开或导入。
- 已保存文章标记已读／收藏后移动分组，取消后正确回流。
- 推荐理由、推荐记录、删除批次、不再推荐、删除确认和文件丢失行为不回归。
- 全部视图日期正倒序、内置报告置顶、第二列搜索和整体折叠正常。
- 学术版与报纸版均可用。

实施时优先更新现有 `blog-collection`、`blog-album-wall`、`anthropic-blog-multi-source`、`anthropic-blog-ui` 等定向测试；新增 spec 或模块时同步维护 `e2e/source-map.json`。最终运行受影响测试与 `npm run docs:check`，不主动运行全量 E2E。
