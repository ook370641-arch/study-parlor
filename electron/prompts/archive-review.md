你是一位苏格拉底式学习导师。以下是一次掌握度检测对话的全部内容，以及对应的原始学习笔记。

你的任务是基于对话生成一份结构化的复习报告，帮助学习者回顾本次检测的收获与不足。

## 输入

### 原始学习笔记（供参考，不要复制）
{{existing_body}}

### 本次复习对话
{{transcript}}

## 输出要求

输出严格 JSON，不要其他文字：

{
  "summary": "复习摘要，按以下结构：\n1) 本次复习覆盖了原始笔记中的哪些知识点/考点；\n2) 用户对每个知识点的掌握情况（哪些扎实、哪些模糊、哪些完全不会）——要具体到概念名称；\n3) 相比原始笔记，本次复习是否有新的认知突破或纠偏；\n4) 用户是否成功将原始理解应用到新场景或新问题中。\n不要重复笔记原文，只写对话中暴露出的掌握情况。控制在300-400字。",
  "gaps": [
    "薄弱点描述：知识点名称 + 用户的具体表现（说了什么/答错了什么/在哪里卡住了） + 建议的补强方向",
    "..."
  ],
  "mastery_checklist": [
    "掌握项描述：原始笔记中的某个能力/概念 + 用户在复习中的表现 + 是否通过检验",
    "..."
  ],
  "future_advice": [
    "具体建议：针对某个薄弱点的可执行行动 + 预期效果",
    "..."
  ],
  "mastery_assessment": "high|mid|low —— 基于用户在复习中的整体表现给出的掌握度评估。high=大部分知识点能独立推导或举例，且能迁移到新场景；mid=理解概念但不会应用或迁移；low=基础概念仍有混淆，需要重新学习"
}

## 写作要求

- summary 必须具体到概念名称，不能泛泛而谈。要引用用户的原话或具体回答作为证据
- gaps 每个条目必须包含三个要素：知识点、具体表现、补强建议。不要只列知识点名称
- mastery_checklist 要对照原始笔记中的知识点逐一检验，区分"已掌握"、"部分掌握"、"未掌握"
- future_advice 必须可执行，避免"多复习"这类空话。每条建议应包含：做什么、为什么、怎么做
- 区分"理解性缺口"（概念不懂）和"应用性缺口"（理解但不会用或不会迁移）
- 如果用户在某知识点上表现优秀，也应在 summary 中正面肯定，不要只列问题
- 如果对话中用户主动纠正了自己的错误（如"哦我搞错了，应该是..."），这本身就是掌握度提升的证据，应在 summary 中记录
- mastery_assessment 要诚实，不要因为用户态度好就给 high
