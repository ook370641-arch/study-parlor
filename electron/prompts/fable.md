# 任务

根据以下学习材料，生成一则关于「{{topic}}」的寓言式概念讲解。

## 输入材料

以下三项中只有一项或两项会有内容。标记为【未提供】的项请直接忽略：

### 对话记录
{{transcript}}

### 学习报告
{{reportBody}}

### 用户风格偏好
{{userPrompt}}

> 如果对话记录为【未提供】或极短（少于3轮问答），仍按下方规则生成，不要输出错误信息。

## 生成策略

- **基于对话记录**（提供了 transcript）：基于对话中的问答脉络提取核心概念，故事正文 800-2000 字
- **基于学习报告**（提供了 reportBody）：基于报告的结构化内容提取核心概念，故事正文 1500-2500 字
- **两者都提供**：以学习报告为主，对话记录为辅，故事正文 1500-2500 字
- **用户风格偏好非空**：在文学性标准基础上，额外融入用户指定的风格倾向
- **用户风格偏好为空**：使用默认风格——温暖、含蓄、略带哲思，避免说教感

## 要求

1. 用故事/寓言的方式间接讲授核心概念
2. 故事在"领悟时刻"才点破概念——"领悟时刻"定义为：角色通过自身行动/观察自然得出结论之后、解释段开始之前。解释段必须独立成段，与故事正文用空行分隔
3. 故事后补充一段精确解释，点破隐喻。解释段必须：
   - 以"这个故事讲的是……"或类似句式开头
   - 逐一对照：故事中的每个核心元素（角色、物品、场景、冲突）分别对应{{topic}}的哪个概念
   - 最后一句点明：这个寓言如何帮助理解{{topic}}的本质
4. 语言风格要求（四项必须同时满足）：
   - 具象化：核心概念必须映射为可感知的角色、物品、场景或自然现象，禁止抽象名词直接出场
   - 情节驱动：故事必须有"失衡→探索→转折→领悟"的完整弧线，禁止平铺直叙的说明
   - 感官细节：至少包含2处视觉/听觉/触觉的具象描写，让读者能"看见"故事
   - 留白节奏：解释段之前至少保留3个叙事节拍（场景/对话/动作），让概念自然浮现而非被宣布
5. 故事要有角色、情节、冲突、转折
6. 故事正文（不含解释段）800-2500 字。基于报告生成时取 1500-2500，基于对话生成时取 800-2000，禁止为了凑字数添加无关情节
7. 中文，文学性强，适合深度理解
8. **只输出纯 JSON，不要 markdown 代码块，不要任何额外文字**

## 可行性检查

如果输入材料过于零散、缺乏核心概念，或{{topic}}本身不适合故事化（如纯操作步骤、纯数值计算），则生成一则"微型寓言"（300-500字）：用一个极简场景隐喻"学习本身就是一个探索过程"，并在解释段诚实说明"本次学习材料更适合直接总结，以下为辅助理解的类比"。禁止强行编造不存在的概念。

## 输出格式

{
  "title": "寓言标题",
  "body": "完整的寓言正文（包含故事 + 解释段）"
}
