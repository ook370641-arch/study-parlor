# /fable — 寓言式概念讲授

## 首次使用配置

**每次触发 `/fable` 时，先检查是否已完成路径配置：**

读取本 SKILL.md 文件内容，检查是否包含 `YOUR_LIBRARY_PATH`：

- **如果已替换为实际路径**（如 `C:/Users/.../学习库`）：跳过本步骤，直接使用该路径
- **如果仍是 `YOUR_LIBRARY_PATH`**：执行以下配置流程

### 配置流程

1. **询问应用位置**

   > "首次使用 /fable，需要配置学习库路径。请提供 Study Parlor 项目在本地的根目录路径（包含 `.env` 文件的目录），例如：`C:/Users/你的名字/Desktop/Study tutor`"

2. **读取 `.env` 并提取路径**

   使用用户提供的目录，拼接 `.env` 路径并读取：
   ```bash
   cat "{用户提供的目录}/.env" | grep STUDY_LIBRARY_PATH
   ```

   - 如果读取成功，提取 `STUDY_LIBRARY_PATH` 的值（去掉等号左边，取右边）
   - 如果读取失败，提示用户检查路径是否正确，并重新询问

3. **写入配置到本 skill**

   提取到路径后，用以下命令把本 SKILL.md 中所有 `YOUR_LIBRARY_PATH` 替换为实际路径（ skill 自修改，一次配置永久生效）：

   **Windows (PowerShell):**
   ```powershell
   $skillPath = "{本 skill 的 SKILL.md 完整路径}"
   $content = Get-Content $skillPath -Raw
   $content = $content -replace 'YOUR_LIBRARY_PATH', '{提取到的实际路径}'
   Set-Content $skillPath $content -NoNewline
   ```

   **macOS / Linux:**
   ```bash
   sed -i 's|YOUR_LIBRARY_PATH|{提取到的实际路径}|g' "{本 skill 的 SKILL.md 完整路径}"
   ```

   > **注意**：替换后 SKILL.md 中所有 `YOUR_LIBRARY_PATH` 都会变成实际路径，包括保存配置、扫描存档目录、创建目录、写入文件等所有位置。

4. **确认配置完成**

   > "学习库路径已配置为 `{实际路径}`，下次使用 /fable 无需再配置。"

## 保存配置

- **学习库根目录**：`YOUR_LIBRARY_PATH`（首次使用时会通过上述配置流程自动替换为实际路径）
- **保存位置**：`YOUR_LIBRARY_PATH/{概念名}/s{编号}/寓言.md`
- **Session 编号**：新概念从 `s1` 开始；已有概念取最大 session 编号 + 1
- **保存时机**：寓言讲完、用户反馈结束后主动询问，用户同意才保存
- **禁止行为**：讲述过程中**不自动保存**，不中途写入文件

## 触发时同步进度（第一步）

每次触发 `/fable` 时，先执行以下步骤：

1. **扫描学习库**：
   ```bash
   ls "YOUR_LIBRARY_PATH"
   ```

2. **解析历史记录**：
   遍历学习库下的概念目录，读取每个 `sN/寓言.md` 的 frontmatter：
   - 概念名 = 目录名（即文件夹名）
   - session 次数 = 该概念下 `s\d+` 目录中包含 `寓言.md` 的数量

   **匹配当前概念后，必须告知用户：**
   - 如果有历史记录：
     > "你之前学过 **[概念]** 的寓言，这是第 **n** 次学习。上次讲的是 **[简要摘要]**。要换一个概念还是继续深入？"
   - 如果没有历史记录：
     > "这是你在 **[概念]** 的第 **1** 次寓言学习。"

3. **主题/领域提取规则**：
   - 用户明确说"用寓言讲注意力机制" → 概念="注意力机制"
   - 用户说"/fable"或"fable" → 问"想从哪个领域选概念？"
   - 用户说"讲个故事" → 问"想听哪个领域的故事？"

## 寓言讲述规则（核心）

**流程**：
1. **选概念**：从用户指定的领域选一个研究生水平的概念（如 Transformer、熵增、纳什均衡、贝叶斯推断等）
2. **写寓言**：用一个完整的故事间接讲授这个概念
   - 故事要有角色、情节、冲突、转折
   - 概念的各个要素要映射到故事的各个元素
   - **直到故事快结尾时，读者才慢慢意识到"原来讲的是这个概念"**
3. **点破隐喻**：故事结束后，补充一段精确解释
   - 明确指出故事中的每个元素对应概念的哪个部分
   - 给出概念的正式定义
   - 解释为什么用这个故事来映射这个概念

**风格要求**：
- 故事要完整、有文学性，不是简单的比喻堆砌
- 可以是童话、科幻、历史、日常生活等任何体裁
- 长度适中：1500-3000 字
- 讲述时保持叙述的流畅性，不要让概念术语过早出现

## 延迟存档机制（关键）

**讲述过程中**：
- 在内部累积寓言内容和解释（不写入任何文件）
- 不自动保存，不提示保存

**检测反馈结束信号**（当用户说出以下任何一种时）：
- "明白了" / "懂了" / "懂了懂了"
- "有意思" / "精彩" / "写得好"
- "存一下吧" / "保存" / "记下来"
- "今天就到这里" / "够了" / "可以了"
- "换个概念" / "再讲一个"（当前寓言结束，准备存档后再开始新的）
- 用户在寓言和解释发表后 2 轮内没有继续提问

**主动询问存档**：
检测到反馈结束信号后，**主动问用户**：

> "这个寓言可以存档吗？会按 Study Parlor 学习库规范写入，文件保存在 `学习库/{概念名}/s{编号}/寓言.md`。"

**用户回应处理**：
- **同意**（"可以"、"好"、"存"、"保存"、"行"、"嗯"）：执行保存
- **不同意**（"不用"、"不存"、"不需要"、"下次吧"）：不保存，但告知"好的，未存档。"
- **模糊**（没明确回答）：再问一次"需要存档吗？"

## 保存执行（用户同意后）

**步骤 1：确定保存位置**

1. 概念名 = 从对话中提取的核心概念（**必须**经过用户确认或用户已明确同意）
2. 扫描 `YOUR_LIBRARY_PATH/{概念名}/` 下的所有 `s\d+` 目录
3. 计算下一个 session 编号：
   - 如果概念目录不存在或没有 `s\d+` 子目录 → `s1`
   - 否则 → 取现有最大编号 + 1
4. 目标路径：`YOUR_LIBRARY_PATH/{概念名}/s{编号}/寓言.md`

**步骤 2：生成 frontmatter**

按 Study Parlor 的 `Frontmatter` schema 生成 YAML frontmatter：

```yaml
---
title: "{概念名}"
description: "{一句话描述本次寓言的核心内容}"
type: fable
created: '{ISO 时间戳}'
tags:
  - {根据内容推断的 tag1}
  - {根据内容推断的 tag2}
  - {根据内容推断的 tag3}
session_number: {编号}
difficulty: high
progress_summary: >-
  {多行文本总结本次寓言的核心收获}
last_studied: '{ISO 时间戳}'
review_count: 0
---
```

**字段规则**：
- `title`：概念名
- `description`：一句话描述本次寓言的核心内容
- `type`：**固定 `fable`**
- `created` / `last_studied`：当前时间 ISO 格式，**用单引号包裹**
- `tags`：根据概念内容推断 2-4 个相关标签
- `session_number`：该 session 的编号
- `difficulty`：**固定 `high`**
- `progress_summary`：使用 `>-` 多行折叠标量格式，建议控制在 100-200 字
- `review_count`：复习次数，初始为 0

**步骤 3：生成报告正文**

报告正文使用以下固定模板：

```markdown
# {概念名}

## 第 {编号} 次寓言学习

**日期**：YYYY-MM-DD  
**模式**：寓言式概念讲授  
**领域**：[用户指定的领域]

---

## 寓言

[完整的故事文本]

---

## 概念解释

[点破隐喻的精确解释：故事中的每个元素对应概念的哪个部分，正式定义，为什么用这个寓言]

---

## 用户反馈

[用户对寓言的反馈和理解]
```

**步骤 4：写入文件**

1. 创建目录：`mkdir -p "YOUR_LIBRARY_PATH/{概念名}/s{编号}"`
2. 写入文件：把 frontmatter + 正文写入 `寓言.md`

完整命令示例：
```bash
mkdir -p "YOUR_LIBRARY_PATH/注意力机制/s1"
echo "---
title: 注意力机制
description: 通过森林传信的故事理解注意力权重分配
type: fable
created: '2026-05-27T11:10:28.000Z'
tags:
  - AI
  - 深度学习
  - 注意力机制
session_number: 1
difficulty: high
progress_summary: 通过寓言理解了注意力机制的核心：查询-键-值的交互，以及 softmax 归一化的作用
last_studied: '2026-05-27T11:10:28.000Z'
review_count: 0
---

# 注意力机制

## 第 1 次寓言学习
..." > "YOUR_LIBRARY_PATH/注意力机制/s1/寓言.md"
```

## 特殊情况

**用户想连续听多个寓言**：
- 每个寓言讲完后询问是否存档当前寓言
- 如果用户说"再讲一个"，先处理当前寓言的存档（存或不存），再开始新的

**用户中途打断**：
- 如果用户在故事中间说"换个概念"，询问是否放弃当前故事（不存档）

**概念目录不存在**：
- 自动创建：`mkdir -p "YOUR_LIBRARY_PATH/{概念名}/s1"`
