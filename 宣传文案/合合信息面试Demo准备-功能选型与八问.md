# 合合信息面试 Demo 准备：功能选型、八问口径与补强清单

> 用途：2026-10-29 合合信息 AI 产品方向面试 Demo。
>
> 本文不是产品宣传稿，而是一份现场展示与追问的工作底稿。原则：只展示能讲清用户、机制、边界和验证指标的真实功能；不靠视觉氛围或“AI 很酷”撑场。
>
> **一句话主线**：把一份本地长文档从“难以阅读的 PDF”变成可寻址的章节、可解释的导读、可沉淀的笔记和可复用的个人知识资产。

---

## 0. 推荐展示组合

### 结论

- **主展示：书籍来源 / 长 PDF 阅读链**（约 5–6 分钟）
- **辅助展示一：章节旁注与上下文问答**（约 1–2 分钟）
- **辅助展示二：复习报告 → 知识缺口 / 掌握检验 / SVG 学习图表**（约 1–2 分钟）
- **可选收尾：寓言生成**（30 秒，作为“编码与记忆”的差异化表达）

不要把“苏格拉底夜话、写作助手、Anthropic 博客、画作、语录”等入口都点一遍。它们可以证明产品宽度，但会稀释“文档理解 + 可靠工作流”的核心叙事。

### 与合合信息的对应关系

| 应用能力 | 面试中对应合合的能力 / 视角 | 应该怎么说 |
|---|---|---|
| PDF 导入、文字层检测、目录识别、按章切分 | xParse 的“文档 → 结构化数据” | “我当前是用 pdfjs 做轻量实现，重点验证下游体验。若接 xParse，可以直接得到更稳的 Markdown、标题层级、表格、坐标与证据链。” |
| 章节导读、检索规划、生成过程、旁注与笔记 | DocFlow / 文档 Agent 的“结构 → 任务流” | “解析不是终点；结构化后的文档对象，才能进入可解释、可回退、可沉淀的任务链。” |
| 边界、错误提示、降级 | 合合强调的确定性、可追溯性 | “我不把失败藏在模型背后：扫描件拒绝入架、无目录回退整书单章、生成格式不合法不写入。” |
| 本地 Markdown、边车文件 | 企业文档的可控性 / 可迁移性 | “学习记录、导读、旁注、笔记都落在用户自己的本地目录中，不锁在黑盒数据库。” |

**关键定位**：不要说“我做了一个 xParse”。正确说法是：**“我做的是 xParse / 文档解析能力的下游 Agent 体验：把解析后的结构真正变成读得完、记得住、会回来的学习闭环。”**

## 1. 主展示：书籍来源——长 PDF 到可持续学习闭环

### 1.1 展示目标与 90 秒话术

**展示目标**：让面试官看到，应用不是把 PDF 丢给大模型总结，而是先把文档变成一个可定位、可复用、可追溯的章节结构，再对每章提供不同深度的 AI 服务。

> “我选的是读长 PDF 的知识工作者。痛点不是没有总结工具，而是本地 PDF 往往读不完；即使读了，目录、段落理解和自己的笔记又散在不同地方。
>
> 所以我把一本书定义为一个来源，把章节定义为可操作的文章。导入时，应用检测 PDF 是否有文字层，识别目录并按章节切成真实 Markdown 文件；打开任意章节后，用户可以看目录感知的导读、对照自己的写作、对选中段落做旁注，最后把它存成关联这本书的笔记。
>
> 这条链的重点不是‘AI 总结 PDF’，而是先结构化，再让每一步都有明确的对象、持久化产物和失败边界。”

### 1.2 推荐现场路径

1. 在“夜航简报”进入 **书籍**来源。
2. 导入预先准备好的、带文字层和目录的 PDF。**不要现场临时等系统文件选择器或 LLM。**
3. 展示书籍卡片：书名、章节数量、全书导读（提前预热缓存）。
4. 点击一个短章节：显示真实章节正文、页码范围和章节在全书中的位置。
5. 打开右侧“导读”：说明它输入的是“本章正文 + 全书目录 + 已生成的上一章导读摘要”，而不是脱离上下文的一次性摘要。
6. 选中一句关键文字，创建旁注；再在「标注 (n)」列表里点「存」把它存为笔记（笔记正文会自动带上原文摘录和你写的备注）。
7. 切入笔记书架，展示笔记按书名归集。

### 1.3 面试八问：主答案

#### 1. 解决谁的什么问题？

**目标用户**：长期阅读专业书、行业报告、研究资料、公司年报的知识工作者，例如产品经理、研究员、学生和投资研究人员。

**核心问题**：他们拥有很多本地 PDF，但阅读过程断裂：

1. 长文档入口成本高，不知道从哪章开始；
2. 读到关键段落时，理解、摘录、联想和提问在多个工具间跳转；
3. 读完没有形成可继续使用的个人资产，下一次又从头找。

#### 2. 为什么值得解决？

书籍、报告和制度文档仍是高密度知识的主要载体，但它们的阅读体验基本停在“翻页 + 搜索”。

更重要的是，这不是单次效率问题，而是**学习资产无法积累**的问题。用户一旦能把“章节理解、个人旁注、关联笔记、复习”放在同一条链路里，下一次阅读的起点会更高。这是留存来源，而不是一次性的摘要需求。

#### 3. 用户现在不用产品，怎么解决？

| 现有替代方案 | 用户付出的代价 |
|---|---|
| PDF 阅读器 + 高亮 + 手动摘抄 | 高亮和理解脱钩；归档、标题、关联全靠手工 |
| ChatGPT / Claude 上传整份 PDF | 得到一次性对话，章节定位和长期沉淀较弱；用户难以复用自己的历史笔记 |
| 微信读书等电子书平台 | 体验完整，但本地 PDF、企业资料、研究报告不一定可导入或可与个人资料关联 |
| NotebookLM | 适合多资料问答，但在“按章节渐进阅读、段落旁注、写进自己的 Markdown 知识库”上不是其核心体验 |

#### 4. 为什么一定要用 AI？不用 AI 是否更简单？

**不该用 AI 的部分，坚决不用。**

- PDF 是否有文字层、目录页在哪里、目录项和页码如何映射、章节文件如何保存：应使用确定性解析和文件系统逻辑。
- 用户点击“存为笔记”、旁注如何锚定到段落、删除书籍时是否删原件：应使用明确规则和确认机制。

**必须用 AI 的部分，是确定性规则无法完成的“理解工作”。**

- 章节导读要解释“这章在全书论证链的位置、它在回答什么、承接上一章什么”，不是抽取标题或首段。
- 旁注问答要结合用户选中的文字、已有导读、历史旁注和可选外部资料来回答。
- 用户需要的是针对当前章节的理解入口，而不是统一模板。

因此产品不是“用 AI 替代解析”，而是**确定性解析负责建立可信边界，AI 负责在边界内做理解、解释和个性化联想。**

#### 5. 做了什么，又主动砍掉了什么？

已做：PDF 导入与原文件副本保存、文字层检测、目录解析、页码偏移校准、章节 Markdown 化、全书导读、章节导读、对照阅读、旁注、关联笔记。

主动砍掉：

- EPUB / MOBI：没有稳定的合规来源和真实需求验证，不做“格式大全”；
- 扫描版 OCR：当前没有可信的端到端质量与成本方案，检测到无文字层后明确拒绝；
- PDF 原版页面渲染和双栏页码对照：会显著增加视觉与定位复杂度，不影响验证阅读闭环；
- 全书自由问答：整本书直接聊天很容易变成没有章节上下文、成本不可控的“Chat with PDF”；
- PDF 书签解析：现阶段目录页覆盖率更高，缺真实样本就不做预留接口；
- 自动替用户写长篇笔记：先保证“从阅读到笔记”的闭环，不把产品扩成泛写作工具。

#### 6. Agent 在哪些情况下失败？

| 失败情形 | 当前处理 | 面试时应强调的原则 |
|---|---|---|
| 扫描版 PDF 无文字层 | 明确报错，不入架 | 诚实失败优于编造解析结果 |
| 没有目录或目录无法识别 | 回退整书单章，并标记“无目录” | 保留阅读能力，不虚构章节 |
| 页码偏移无法校准 | 按目录页码直接切，边界可能漂移 | 记录不确定性；后续可用结构坐标能力增强 |
| 复杂点线、双栏、多级目录 | 现有规则可能漏章或错配 | 这正是目录解析补强项；更复杂场景应交给专用解析能力 |
| 超长章节 | 整章塞给导读模型会导致延迟、成本、上下文质量失控 | 需要先做长度上限和分段策略 |
| 模型输出不是规定 JSON | 校验失败，不写入错误导读，并保留调试记录 | 生成内容也是协议输出，必须校验 |
| LLM / 搜索服务不可用 | 导读或搜索可降级，不影响已导入的正文、目录、旁注和笔记 | 文档资产不应因模型暂时不可用而消失 |

#### 7. 怎么判断价值？3 个核心指标

1. **章节导读完成率**：完成导读的章节数 / 被打开章节数。验证导读是否真的降低了阅读进入门槛。
2. **沉淀转化率**：至少创建一条旁注或一篇关联笔记的读者数 / 打开书籍读者数。验证理解是否变成资产，而非停留在浏览。
3. **7 日章节回访率**：7 天内再次打开同一本书任一章节、其笔记或复习内容的用户数 / 首次打开书籍用户数。验证是否形成持续学习而非一次性总结。

> 可以补一句：初期不看“导入 PDF 数量”，它可能只是囤积；上述三个指标从进入、沉淀、回访分别覆盖价值漏斗。

#### 8. 再给两周，优先验证什么，而不是继续开发什么？

优先验证：招募 5–8 名有真实长 PDF 的目标用户，每人选择一份正在读但没有读完的材料，完成一次“导入 → 选择章节 → 导读 → 旁注或笔记 → 7 天回访”的任务。

重点观察：

- 他们是否先读导读还是直接读原文；
- 导读是否真正帮助决定“该不该读、先读哪一章”；
- 旁注是因为理解不清、值得记住，还是只是把高亮换了个位置；
- 哪类 PDF 在目录解析和表格阅读上最容易失败。

**不优先开发**：EPUB、扫描 OCR、聊天问整本书、更多主题皮肤。它们会扩张演示面，但不能回答“用户是否愿意持续使用这条闭环”。

## 2. 辅助展示一：旁注——从“高亮”升级到带上下文的理解动作

### 值不值得展示？

**值得，且建议作为书籍主线里的一个 60–90 秒动作，不要独立讲成大功能。**

它是书籍链中最能证明“用户不只是被动接收 AI 总结”的一环：用户主动选择一个段落，写下自己的疑问和判断，AI 才基于所选文字、章节正文、导读、历史旁注和可选搜索资料回复。

### 真实机制

1. 用户在正文中选择文本；
2. 应用记录选中文本与段落索引，在正文上加可点击的笔形锚点；
3. 旁注以同名 `.annotations.md` 边车文件存储，而不是藏入数据库；
4. 该章节的 AI 旁注对话可读取文章全文、导读摘要、用户旁注与当前选区；
5. 旁注可进一步“存为笔记”，进入笔记书架。

### 为什么它比“AI 聊天框”更值得讲？

普通聊天框要求用户自己描述上下文，且聊天记录很容易离开原文。旁注把上下文固定在一段可回到原文的位置上：**用户的思考、AI 的回答与证据文本三者绑定。**

这也贴合合合强调的“审核依据回显”——不是只给结论，而是保留“这个结论是针对哪一段原文产生的”。但要注意：当前应用的锚定是“段落序号 + 选中文本”，不是像 xParse 一样的 PDF 坐标证据链；这是当前能力边界，不能混说。

### 容易被问到的问题与回答

- **“如果同一句话在一段中出现两次？”**：当前实现优先命中首个文本匹配，属于脆弱点。后续应该保存字符范围 / 结构路径，接入解析坐标后可进一步升级为页码和坐标级证据锚定。
- **“文章改了，旁注怎么办？”**：当前旁注与章节文件同目录存放；正文被大幅改写后可能失锚。对导入后的只读书籍章节可控，但对可编辑文章需要做锚点重定位策略。
- **“为什么不直接用评论？”**：评论是协作语义；旁注服务的是个人理解和阅读中的即时认知动作，两者存储、权限、回顾方式不同。

## 3. 辅助展示二：复习报告与 SVG 学习图表——把一次对话变成下次的起点

### 值不值得展示？

**值得展示复习报告和学习图表；不建议将“发起一次完整复习对话”作为现场主流程。**

原因：复习的“对话过程”受模型实时输出影响，现场不可控；已经生成的复习报告和 SVG 则能完整、稳定地展示这条能力的输入与输出。

### 真实流程

1. 用户从某个已完成主题发起“复习”；
2. 系统读取该主题**最新一份学习报告**，连同描述、学习进度、标签、难度等上下文，进入复习会话；
3. 结束后，LLM 基于“旧报告 + 新对话”生成：复习摘要、知识缺口、掌握检验清单、后续建议；
4. 内容写入同一会话目录的 `复习报告.md`；重复复习会追加内容并更新复习次数与时间；
5. 学习报告还会异步交给 LLM 生成 SVG 学习图表，只有输出确实以 `<svg` 开头才落盘为 `学习图表.svg`。

### 面试中可以怎么定位

> “我不把复习理解成让模型再讲一遍，而是让模型比较‘上次我学到了什么’和‘这次我回答得怎么样’，把差距具体化为可检查的条目。报告与图表不是展示品，而是下一次学习时可被重新读取的状态。”

### 它适合回答的八问

| 问题 | 可用答案 |
|---|---|
| 解决谁的什么问题 | 自学者容易把“看过”误认为“掌握”，却不知道下一次该从哪里继续。 |
| 为什么 AI | 要结合上次报告与本次对话判断理解缺口，不是固定题库能完成；但清单和归档是确定性写入。 |
| 砍了什么 | 没有做“预测分数”“虚假的精确掌握率”和复杂知识图谱；先交付用户可验证的缺口和下一步。 |
| 失败情形 | 模型可能给空泛总结，或 SVG 不是合法 SVG；前者有降级文案，后者不保存错误文件。 |
| 指标 | 复习发起率、掌握清单完成率、同主题二次 / 三次复习回访率。 |

### SVG 是否值得重点讲？

**能展示，但不要把它包装成核心价值。** 它是“把报告结构视觉化”的好收尾，能体现模型输出后有格式校验和本地持久化；但图表是否真正帮助学习，需要用户研究验证。若面试官追问，主动承认：

> “我把它视为待验证的辅助表达，而不是已被证明的学习效果功能；真正核心指标仍是复习回访和掌握清单完成。”

## 4. 可选收尾：寓言生成——适合做差异化表达，不适合做主功能

### 值不值得展示？

**可以在最后 30 秒展示成品，但不要展开讲，也不要现场等待生成。**

它的价值是把抽象概念重新编码为人物和情节，降低日后回忆的检索成本；用户还能选择风格标签或补充要求。它会从会话或已归档的学习报告中生成一篇本地 Markdown 寓言。

### 为什么不做主线？

- “故事帮助记忆”有合理机制，但本项目尚未验证其是否比短摘要 / 练习题更有效；
- 它与合合的文档解析 / 业务流程主线较远；
- 若讲得太久，容易被理解为为了炫生成内容而生成内容。

**推荐收口话术**：

> “最后这个寓言不是为了展示文风，而是一个很小的假设：对抽象概念，换一种叙事编码可能让人更容易在一周后回忆。它值得被 A/B 验证；没有验证前，我不会把它当核心价值。”

这句话比直接展示一篇漂亮故事更显产品判断。

## 5. 其他功能的取舍

| 功能 | 建议 | 原因 |
|---|---|---|
| 苏格拉底式夜话 | 不作本次主展示 | 是产品原点，但难在短 demo 内证明“比直接回答更有效”；可在产品背景页一句带过。 |
| 写作助手 Agent（本地读取 / 网络搜索） | 面试官主动问 Agent 时再展示 | 有原生工具调用、上限与失败反馈，工程上可讲；但任务过宽，和本次“文档理解”主线不如书籍链聚焦。 |
| Anthropic 博客来源 | 不展示 | 依赖外部抓取与网络，现场稳定性差，与用户真实资料的关系弱。 |
| 主题推荐 / 续谈建议 | 不展示 | 价值较弱、证据不足，容易被认为是常见生成式功能。 |
| 笔记书架 / 专辑墙 | 作为主线最后一跳展示 | 它证明内容沉淀，但不是 AI 亮点；用来收口“资产归属用户”即可。 |
| 画作、主题、语录、灯火 UI | 只做视觉背景 | 能体现体验品味，不要花语言解释。 |

## 6. 两项必须补强：为什么必要做

### 6.1 目录解析的点线支持：这是“可信结构”的正确性问题

#### 已实测的问题

使用本地的《合合信息 2025 年年度报告》做抽取验证：274 页、约 20.7 万字，目录页有 8 个一级章节。

当前目录解析器识别行内目录使用规则：`标题 + 空白 + 页码`。年报目录使用的是 `标题 + 点线引导符 + 页码`，且部分行页码前没有空格。例如：

```text
第一节 释义 ...................................................................... 5
第二节 公司简介和主要财务指标 ............................................................7
```

结果是：当前逻辑只识别出 6 个章节，漏掉“第二节”“第四节”；第 1 章会被切到第 2 章前。这会直接破坏“按章节阅读”的基本承诺。

#### 为什么必须做，而不只是小优化？

1. **这是主 demo 的输入正确性。** 主线说“目录解析 → 章节导读”，一旦目录错了，导读、旁注、笔记全都绑定到错误的章节对象；后续 AI 再聪明也无法修复错误输入。
2. **这是合合场景下最容易被追问的地方。** 面试官做文档解析，会天然问“目录不规则怎么办”。如果你刚好拿合合年报演示却切错章节，可信度会反转。
3. **改动小、收益确定。** 预处理目录行时移除连续点线 / 省略号引导符，再用标题页码配对，即可从 6/8 提升到 8/8；它不改变数据模型，不扩大功能范围。
4. **能体现正确的产品优先级。** 与其加一个新格式、一个新模型开关，不如先补输入层最影响用户信任的一处解析规则。

#### 推荐验收条件

- 原有“行内标题 + 空格 + 页码”及“标题块 + 页码块”用例继续通过；
- 增加真实年报风格 fixture：点线引导符、页码前无空格；
- 目录项应稳定解析为 8 条，标题不含引导点，页码正确；
- 以该目录切章时，第 1 章结束在第 2 章前、第 2 / 4 章不再缺失。

### 6.2 章节导读长度上限：这是 Agent 的成本、时延与质量边界问题

#### 已实测的问题

年报经正确切章后，章节长度差异非常大：

| 章节 | 文本长度 | 粗略 token 量 |
|---|---:|---:|
| 第一节 释义 | 2,280 字 | 约 1.4k |
| 第二节 公司简介和主要财务指标 | 5,210 字 | 约 3.3k |
| 第三节 管理层讨论与分析 | 35,805 字 | 约 22k |
| 第五节 重要事项 | 37,325 字 | 约 23k |
| 第八节 财务报告 | 115,005 字 | 约 72k |

当前章节导读会把“书籍上下文 + 整章正文”直接传给导读管线；没有针对书籍章节的输入上限或分段策略。

#### 为什么必须做，而不只是性能优化？

1. **用户体验不可控。** 72k token 的章节会显著拉长等待时间，甚至接近或超过不同模型的上下文 / 输出稳定区间。用户点击“导读”后不知道是在生成、卡住还是失败。
2. **成本不可控。** 同样点击一次导读，大章节可能消耗短章节几十倍 token；这无法形成可运营的成本模型。
3. **导读质量不一定随输入变长而提升。** 财务报告里包含大量表格、附注和重复披露；把它们无差别塞入 prompt，会稀释真正该被解释的论证结构。
4. **这是对“Agent 不会无限吞文档”的基本承诺。** 合合的文档能力强调结构化，正确做法不是把长文直接丢给模型，而是根据结构控制上下文。

#### 建议的最小实现（本次 demo 足够）

不要粗暴地截取前 N 个字符。优先按以下顺序处理：

1. 设定总输入字符 / token 预算；
2. 优先保留书籍上下文、章节标题和章节内 H2/H3 标题；
3. 正文超限时，按标题切成片段，仅生成“本章概览 + 各片段摘要”，再合成为最终导读；
4. UI 显示“本章较长，已按 X 个部分生成导读”，让用户知道系统做了什么；
5. 首次 demo 可先选择短章节预热，避免把长文处理策略当作现场演示风险。

如果两天时间只能选一个简化版本：**先做明确的上限 + 可见提示 + 失败不写入**，然后再做按标题分段的层级导读。绝不能继续无上限直传。

## 9. 现场走查发现的问题（2026-10-27，按严重度）

> 这一节是我自己以面试官视角点了一遍主展示链路后记下的问题。**写在这里的目的不是遮丑，而是决定 demo 顺序与话术**：哪些必须先修，哪些用一句话承认即可。
>
> 严重度定义：**S1 = 会当场破坏主线叙事**（观众会得出错误结论）；**S2 = 明显掉体验分**；**S3 = 细节，可以不提**。

### S1-1 折叠列后内容被挤成碎片

**现象**：点书籍列 / 章节列的收起按钮，卡片不是消失，而是被压进 56px 的窄条里，书名、章节名截成一列碎字。

**为什么是 S1**：这是 demo 里**唯一一个会让观众当场怀疑“这是不是没做完”的视觉信号**。它出现在整条链路的第一步（选书 → 选章），第一印象一旦坏掉，后面讲得再好都在补锅。

**处理**：改在公共组件 `BriefingListColumn`，折叠即不渲染内容（与写作页 2026-10-22 的修法一致）。**✅ 已修复（2026-10-27）**——折叠时列表内容整体卸载，只留展开按钮；博客列的缩略图 rail 走 `renderWhenCollapsed` 显式保留。演示时可以放心点收起。

### S1-2 正文被抽成一坨，看不出“结构化”

**现象**：JTBD 章节里出现 `21-year-` / `old men` 断行、独立页码 `5` 夹在段落中间、每个视觉行都硬换行。导入后的 Markdown 段落边界是假的。

**为什么是 S1**：主线的第一句就是“先把 PDF 变成可寻址的章节结构，再谈 AI”。如果正文连段落都不成立，“结构化”就是空话——而且面试官只要滚两下鼠标就能看到。**这是逻辑自相矛盾，比视觉问题更致命。**

**处理**：重写行 → 段落的重建规则（间距补空格、去页码孤行、还原连字符、按句末合并），旧书提供“重新解析”。**✅ 已修复（2026-10-27）**——新管线 `itemsToLines → linesToParagraphs → paragraphsToMarkdown`；旧书书架卡片显示「解析格式较旧 · 重新解析」，原地重解析并自动清掉导读缓存。**演示前必须先对目标书点一次重新解析**，否则看到仍是旧文本。

### S2-1 导读生成过程只有一条 1px 线

**现象**：右侧导读栏在生成时只有“检索背景资料中… 1/3”和一条细线，检索了几个查询、命中多少资料完全不可见。

**为什么是 S2**：“Agent 在做什么”本来是这条链路最有说服力的部分，现在被压成一次等待。不会让观众得出错误结论，但会白白浪费一个讲机制的机会。

**处理**：换成 SVG 三阶段可视化（规划 → 检索节点 → 逐条撰写），只用现有进度数字驱动，不造假数据。**✅ 已修复（2026-10-27），2026-10-28 改版**——`GuideCompass` 组件：规划阶段扫描文档轮廓 + 旋转虚线环；检索阶段按查询数生成节点（命中条数决定外圈大小，已完成节点有虚线连到资料夹）；撰写阶段按章节逐格点亮。`prefers-reduced-motion` 下自动降级为静态色块。

加载态版面也重做了：方形罗盘按侧栏宽度放大，占满没有正文的空白，居中一行状态字；画作与作者语录则补在**书籍章节正文顶部**（与文章页、笔记页同一套位置和开关），不再塞进侧栏。文案从工程词换成夜读语气：**展卷定章… → 循迹访书… 1 / 2 处 → 落笔成文… 第 3 节，共 14 节 · 已落 860 字**。

> 讲法提示：这三句话本身就是一段可念的叙事——「先展卷定下这一章要问什么，再循着线索去访书，最后落笔成文」。比「检索了 1/2」更像一支笔在动。

### S2-2 书籍“对照”里没有新建笔记入口

**现象**：书籍对照 tab 打开挑选器，笔记段没有“＋ 新建”，只能挑已有内容。博客有，书籍没有。

**为什么是 S2**：它砍掉了“阅读 → 沉淀”的最后一跳，而这个跳正是产品价值主张。观众不会知道“本来应该有”，但现场演示“存为笔记 → 去笔记里找到”时只能退回正文页操作，动作会显得绕。

**处理**：按章节创建/复用笔记（标题 `<书名> · <章节标题>`，按 `source=book + book + title` 去重），创建后直接进对照槽。**✅ 已修复（2026-10-27）**——对照挑选器笔记段有「＋ 新建」，创建后笔记直接进对照槽；同章二次打开入口自动收起。**这里反而是一个好的讲点**：可以主动说「这是自己走查后补的」——它体现的是你发现了「阅读 → 沉淀」闭环的断点，而不是功能堆砌。

### S2-3 正文工具行的「存为笔记」只建一条空笔记

**现象**：章节正文题下有三个工具：「标注 (n)」「存为笔记」。点「存为笔记」，界面只弹一句 toast，笔记书架里多出一条**只有标题、没有正文**的笔记，正文不跳转、旁注也不带走。

**为什么是 S2**：这是我在自己的 demo 脚本里推荐点击的动作之一（见 §1.2 第 6 步）。面试官看到按钮叫「存为笔记」，会期待它保存了「我正在读的东西」；结果什么都没存，追问一句就很难解释。它伤的是「沉淀」这个价值主张的可信度，不是单纯的功能缺少。

**处理**：直接删除，不做「把整章正文塞进笔记」的替代——那只是把复制粘贴包装成功能。删掉后仍有两个**内容不同、职责不重叠**的沉淀入口：

| 入口 | 产生什么 | 什么时候用 |
|---|---|---|
| 旁注列表里的「存」 | 笔记正文 = 原文摘录 + 自己的备注 | 读到某一句想把它带走 |
| 对照挑选器的「＋ 新建」 | 按章节建/复用笔记，并直接放进对照槽 | 边读边写、对照自己的旧文 |

**✅ 已修复（2026-10-28）**——`BookReader` 的工具行只剩旁注入口（无旁注时整行不占位）；E2E 的「笔记落到书架」断言改走对照新建路径，最后一跳仍有覆盖。

### S2-4 导读加载动画贴在侧栏左侧

**现象**：导读生成时，罗盘动画的构图重心不在侧栏中间。撰写阶段最明显：画面上只有一页文档，位置在左半边，右侧大片空白。

**为什么是 S2**：导读生成是 demo 里**唯一一段需要观众等待 10 秒以上**的空白时间，这段时间的画面就是「产品在思考」的全部证据。动画歪在一边，观众的第一印象是「没做完」，而不是「在检索」。

**处理**：三个阶段的构图重心本来就不同（规划/撰写只有文档，检索是文档 + 节点弧 + 资料夹），现在按阶段把整组内容平移到视口正中。**✅ 已修复（2026-10-28）**——`GuideCompass` 的 `STAGE_SHIFT`；截图核对三个阶段的文档都落在侧栏中线上。

### S3-1 长书名 / 长章节名 / 全书导读被截断

**现象**：书卡书名单行省略、全书导读两行截断、章节名单行省略，且没有完整查看方式（章节项只有原生 title，1 秒后才出现）。

**为什么是 S3**：不影响理解主线，长名字在 demo 书里也不一定出现。但走查时确实“看不全”，处理成本低。

**处理**：hover 350ms 显示全文气泡，只在真正截断时出现。**✅ 已修复（2026-10-27）**——书卡书名、全书导读、章节列表均接入自建 `Tooltip`（portal 到 body，避免被列容器裁切）。未截断时不弹；Esc / 滚动 / 失焦关闭。

### 对 demo 顺序的影响

**7 项已于 2026-10-27 / 10-28 全部修复**（实现记录见 `docs/superpowers/specs/2026-10-27-books-reading-polish-design.md` §6–§9）。修复后的演示含义：

1. **收起按钮现在可以点**：折叠是干净的，甚至可以作为一个「细节做完了」的小证据。
2. **拆解章节结构的过程现在可见**：S2-1 的 SVG 罗盘把「Agent 在查什么」变成现场画面，这是八问里“为什么用 AI / 怎么失败”最直观的证据——**值得在导读那 30 秒里停一下，让观众看检索节点亮起来**。
3. **对照新建笔记可以顺手演示**：从正文旁注 → 存为笔记 → 对照槽，链条完整，不用退回正文页。
4. **「存为笔记」只剩一个含义**：正文工具行里那个空笔记按钮已删除（S2-3），现场要讲沉淀就点旁注列表里的「存」，或对照里的「＋ 新建」——不要解释两个同名入口。
5. **等待时间也是画面**：罗盘三段构图都居中了（S2-4），观众盯着等的时候，画面不会露出「没做完」的痕迹。
6. **但正文必须先重解析**：旧书卡片上会显示「解析格式较旧」，点一次「重新解析」，等它跑完再排练。这一步漏了，正文还是旧的。

### Demo 前的最后检查（4 条）

1. 打开要演示的书 → 若书卡上有「解析格式较旧」→ 点「重新解析」→ 确认正文章节里段落完整、没有孤立页码。
2. 收起再展开书籍列与章节列，确认只剩 `▶` 按钮、没有碎字。
3. 打开一个未生成导读的章节，看一遍 SVG 罗盘三阶段：画面应在侧栏正中，确认动画在你机器上流畅（`prefers-reduced-motion` 开启时会静态化，这是预期行为）。
4. 确认章节题下没有「存为笔记」按钮；要演示沉淀，走「添加旁注 → 标注 (n) → 存」或「对照 → ＋ 新建」。
